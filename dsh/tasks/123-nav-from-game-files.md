# 任务 123:寻路用游戏文件的碰撞和出口——没去过的图也能提前规划

工作目录 `dsh/`。可以改 `src/engine/regions.ts`、`src/engine/atlas.ts`、`src/engine/skills/travel.ts`、`src/engine/skills/move.ts`、`src/engine/nav.ts`、`test/` 下相关测试。**不碰** `src/engine/knowledge/`(任务 121 同时在改;任务 120 的 `knowledge/game-files.ts` 只读它的类型和导出)、`src/engine/stage/`、`src/engine/route/`、`src/engine/game.ts`(若必须改 `game.ts` 的一两处接线，回报里写明改了哪几行)。不碰 `../bridge/`、`../deploy/`、`../agent/`,不碰 git,**不连笔记本**,**不用 docker、不绕开沙箱**。游戏数据只在 `../.deps/`,测试数据自己编。

## 起因(11-11)

寻路的最大短板是只认走过的图：没去过的图没有碰撞和出口，`mapPath` 只能把它当成“进去再看”的一整块，长路径提前算不出来。任务 120 已把游戏文件整理成 `../.deps/knowledge/ff5/files/maps/<地图编号>.json`(碰撞层原值 0–7、出口 `map_id`/`point_id`、伤害格、暗道、MoveArea),并核对过：**碰撞 44 张图 46087 格与 `../.deps/ds/collision-ff5/` 完全一致;出口 338 条里 333 条与地图记录一致**(不一致的 5 条是地图记录当时没记全)。

## 做法

1. **碰撞的后备来源**:`CollisionStore` 在某张图没有缓存时，用游戏文件的碰撞(格式转成现在缓存的形状;字段含义和 `searchLayer` 怎么取，对照已核对一致的 44 张图);活的碰撞回复和缓存照旧优先(剧情会改图)。
2. **出口的后备来源**:`mapExits` 在地图记录里没有这张图(或这张图的出口没记全)时，补上游戏文件的出口(目标图、格子;落点 `point_id` 能换算成目标图里的格子就填 `land`,查清 `point_id` 指向目标图里哪个物件)。地图记录里“走出来”的东西(`links`、观察到的落点、走不过去)照旧优先、照旧合并。这样 `mapPath` 和区域索引(任务 75)就能覆盖没去过的图。
3. **暗道和伤害地板**:暗道格算可走(标出来，执行时按现有规则);伤害地板并进现有的危险格(任务 70 的 hazard)。
4. **“调查后跳”**(待办 96):同一张图里的区域连通把地图记录里 `how` 为“调查后跳”的单向边算进去(执行时到坎边面向它按确认，看现有的跳跃处理在哪);泰空陨石地 189 的 `(16,20)→(16,22)` 是例子。
5. 来源开关：`MapPathOptions`/`CollisionStore` 加“游戏文件目录”参数，默认 `../.deps/knowledge/<game>/files/maps`,文件不在时行为不变(其他五作、测试)。

## 测试

- 小数据：没有缓存的图从游戏文件得到碰撞;地图记录没有的图从游戏文件得到出口，`mapPath` 能穿过它;记录与游戏文件冲突时记录里走出来的优先;伤害地板进危险格;“调查后跳”的单向边让 189 南北连通(只能单向);
- 真实数据测试(文件不在就跳过):从图尔村(30)到风之神殿 4 层(208)的 `mapPath` 能算出来(经世界地图);从洞窟入口(191)到海盗船(198)能算出来;
- 原有寻路测试照旧通过;`npm run check` 全过。
