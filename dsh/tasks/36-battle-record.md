# 任务 36:战斗记录，加侧栏的「战斗中」「战斗记录」

方案在 MyDesign 的《ffpr-agent-战斗策略方案》§4、§9,你读不到，要点都写在下面。

范围:
- 只改这些:`src/engine/`(新文件 `battle-record.ts`,加上 `skills/battle.ts`、`skills/gambit.ts`、`game.ts` 里接入记录的地方)、`src/plugin/`(路由)、`src/client/index.ts`、`test/`。
- **不碰 `src/engine/strategy/`**:另一个任务正在新建这个目录。
- 不改 `package.json`、`tasks/`、`lib/`、`../agent/`、`../bridge/`、`../deploy/`。
- 不碰 git;不运行 `npm run build`;不运行 `scripts/web.sh`、`scripts/ask.mjs`;不连笔记本。
- **重型检查要排队**：另外几个任务在同时跑。`npm run check` 一律写成 `flock /tmp/ffpr-heavy.lock npm run check`。

## 起因

- 现在每场战斗只记一个结果(ok / 吃力 / 全灭)。哪条规则在起作用、哪条从来没用过、为什么输，都说不清。11-03 那几场全灭，是 Claude 翻探针日志倒推出来的。
- 侧栏「FFPR 策略」只把规则翻成中文列成清单，你看不出这一战是怎么打的。

## 要做的

### 1. 战斗记录(`src/engine/battle-record.ts`)

- 每场战斗一条记录，打完追加一行到 `.deps/ds/battles-<作品>.jsonl`(路径照 `config.ts` 里别的 `.deps/ds` 文件那样推算)。
- 记录里有:
  - 编号、开始和结束时间、地图号和名字;
  - 普通战斗还是首领战;
  - 敌人(名字、编号、最大 HP);
  - 用的哪套表:地图号 + 第几套，或者“首领表”;中途重写过的话，也记下来;
  - 结果:ok / 吃力 / 全灭 / 超时，加上说明;
  - 用时;
  - 每一回合一项(见下);
  - 汇总：每条规则(角色 + 序号)触发几次;用掉的道具;我方受到的、对敌人造成的 HP 变化合计。
- **每一回合记一项**:
  - 时间(从开打算的秒数)、谁行动;
  - 用的规则：第几条，0 表示兜底;
  - **条件当时的值**：在 `gambit.ts` 加一个 `explain(condition, situation)`,把条件里每个词换成当时的值，比如 `ally.hp_pct(38) < 50`;
  - 做了什么、打谁;
  - 这一回合试过但做不到的规则，以及原因(没学会、MP 不够、没有道具……);
  - 行动前后，敌我各单位 HP、MP、状态的变化。只记有变化的单位。
- **预留 `events` 数组**：桥插件以后会推敌人出招的事件，现在先空着，格式写进类型。
- 数据都从 `battle.fight()` 本来就读的战斗菜单里取，**不要为了记录多问桥插件**。
- 引擎里保留“正在打的这一场”的记录，供侧栏实时显示;另外保留最近 30 场的摘要。

### 2. 路由

- 新路由 `GET /api/ffpr/battles?game=ffN`,返回:
  - 正在打的那一场：敌我单位，最近 10 个回合;
  - 最近 30 场的摘要;
- `&id=<编号>` 返回一场的完整记录。
- 和成就、策略路由一样，由根上的面板条目注册一次;引擎没启动时回中文说明(照 `panel.ts` 的写法)。

### 3. 侧栏(`src/client/index.ts`,「FFPR 策略」标签)

在最上面加两块:

- **战斗中**(只在有战斗时显示):
  - 每只敌人一行：名字、编号、HP 条(数字 + 条)、状态;
  - 我方每人一行：名字、HP 条、MP、状态;
  - 下面是最近几个回合，每回合两行：
    - 第一行「时间 谁 → 做了什么 → 打谁(HP 变化)」;
    - 第二行用小一号的灰字写依据「规则 2:ally.hp_pct(38) < 50」，兜底就写「兜底」。
- **战斗记录**:
  - 最近的战斗每场一行：时间、敌人、结果、用时、用掉的道具;
  - 全灭标红，吃力标橙;
  - 点开看每个回合(同上的两行格式)和规则命中汇总。
- 有战斗时每 2 秒刷新一次，没有就照现在的频率。
- 前端规矩照 `dsh/CLAUDE.md`:一个文件，文字由服务端算好，前端只排版。
