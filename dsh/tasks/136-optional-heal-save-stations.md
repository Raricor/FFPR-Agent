# 任务 136:回复点、存档点不是必经站;走不到的可选站跳过，不让整份计划停下

工作目录 `dsh/`。可以改 `src/engine/stage/book-plan.ts`、`src/engine/stage/route-book*.ts`(只为站点类别)、`src/engine/route/`、`src/engine/game.ts`(只为接线)、`test/`。不碰 `src/engine/skills/`、`src/engine/regions.ts`、`src/engine/nav.ts`,不碰 `../bridge/`、`../deploy/`、`../agent/`,不碰 git,**不连笔记本**,**不用 docker、不绕开沙箱**。测试数据自己编。

## 起因(11-11 10:41 真机，风之神殿，任务 131/133 上线后)

「Wind Shrine（风之神殿）」计划 9 站(宝箱 4、交回 2)。执行器先开了 2 楼 (9,11) 帐篷(10 秒，很好),接着回 1 楼去「调查 风之神殿 １层 (10,22)」——那是回复壶——连续 2 次「在 (10, 13) 步行走不过去」,整份计划停下交回模型;模型说“路线书又抢路了”,带理由绕过计划自己去 2 楼存档点。当时全队满血。

## 做法

1. **回复站**只在需要时执行：队伍有人 HP/MP 低于阈值(沿用现有补血规则的阈值 / Config)、有人倒下或有异常，或者下一站是首领(首领前补满);否则跳过，进度里记“满血，跳过回复”。
2. **存档站**:首领前一定执行;其他存档站在距离上次存档超过 N 分钟(Config,默认 10)或刚开过宝箱/打过首领时执行，否则跳过。
3. **可选站走不到就跳过**:回复、存档、`optional` 的站连续失败时记“走不到，跳过”,接着下一站，不交回模型;宝箱/隐藏道具、剧情、首领这些必经站照旧失败就交回(带原因)。
4. **顺序**:回复/存档站不参与“先收集后交回”的全局排序，而是插在“需要它的那一站之前”(首领前、或血量低时离当前位置最近的那个);不为了它来回跑楼层。
5. 测试：满血时跳过回复站;首领前补满并存档;回复站走不到 → 跳过、计划继续;宝箱站走不到 → 交回;不会为回复站下楼再上楼。`npm run check` 全过。
