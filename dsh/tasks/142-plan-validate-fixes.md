# 任务 142:段计划检查的三处误判(商店、出发点、默认小节)

工作目录 `dsh/`。可以改 `src/engine/plan/validate.ts`、`src/engine/plan/facts.ts`、`src/engine/plan/tools.ts`、`src/engine/game.ts`(只为 `plan_facts` 默认小节的接线)、`test/`。**不改** `src/engine/plan/types.ts`,不碰 `src/engine/plan/execute.ts`、`src/plugin/`、`src/engine/prompt.ts`,不碰 `../bridge/`、`../deploy/`、`../agent/`,不碰 git,**不连笔记本**,**不用 docker、不绕开沙箱**。测试数据自己编。

## 起因(11-11 12:23 真机，计划模式第一次由模型交计划)

模型为「Pirate's Hideout and Torna Canal」交的计划(换骑士/白魔/黑魔/武僧、`optimize`、买火炎/冰结/闪雷/治疗/解毒/恢复药×6、前后排;站点：风之神殿 204 存档 → 佐克家 39 → 洞窟 192 刷恶魔蟹 → 195 骷髅开关 → 196 三个宝箱 → …)被检查退回:
- `prep.buy[0..5]`:「这节附近的商店没有卖「火炎」…「恢复药」」——这一节包括图尔村(30,有道具店/武器店/防具店/魔法店),这些都卖。很可能是商品名比较时没去掉 `<IC_…>` 图标标记、或三语名没对上、或“附近商店”只取了节里某几张图。
- 「站点第 1 个：地图 204 不属于这一节，也不在通往它的路上」——204 是人现在所在的风之神殿存档点(上一节的图),在出发点存档合理。
- 另外：人在风之神殿水晶之间(上一节已完成)时，`plan_facts {}` 报「路线书没有当前小节」;应默认取“下一个没完成的节”。

## 做法

1. 商店检查：查清为什么误判，修掉(名字比较用清洗后的名字 + 三语名;“附近商店”包含这一节所有地图所在地区的商店，以及通往这一节路上的城镇)。买不到时的提示写出“这些店有卖：…”。
2. 站点归属：现在所在的图、和从现在位置到这一节路上经过的图(跨图规划能算出来的)都算合法;只有完全无关的图才报错。
3. `plan_facts` 不带 `section`:当前图属于一个没完成的节就取它;否则取路线书顺序里下一个没完成的节;事实开头写明取的是哪一节、为什么。
4. 测试：图标标记/三语名的商品能对上;出发点和路上的图合法、无关的图报错;默认小节的三种情况。`npm run check` 全过。
