# 任务 99:被剧情结束的战斗不再记成“战败”;会移动的机关挡路不记成永久“走不过去”

工作目录 `dsh/`。只许改 `src/engine/keylog.ts`、`src/engine/skills/move.ts`、`src/engine/atlas.ts` 和 `test/` 下相关文件;不碰 `src/engine/stage/`(任务 94–96 在新建)、`src/engine/game.ts`。不碰 git,不连笔记本,**不用 docker、不绕开沙箱**。

## 起因(11-10 真机)

1. **“战斗中止”误标成战败**:`keylog.ts` 判定战斗结果时，胜场和逃跑次数都没增加就当 `lost`,写成「没有打赢「…」(战斗中止)」,事件种类 `defeat`。11-10 实际出现过三种情况都落进这里:
   - 卡纳克城逃脱路上，和中士的战斗被剧情收场(中士说“可恶！真难缠！！”),全队 HP 78%,其实没输;
   - 倒计时到点、城爆炸、游戏结束;
   - 首领战全灭(这个有 `wiped` 判断，写成“全灭”,是对的)。
   AI 和 Claude 都因为“战败(战斗中止)”误判过。
2. **会移动的机关挡路被记成永久“走不过去”**:火力船 270 号图是滑动地板(按开关移动平台;平台是实体，不在碰撞层里,11-10 实测碰撞层前后不变)。几分钟里攒了 18 条“走不过去”,全只见过一次;平台一动这些记录就错了，以后进这张图会误导寻路。

## 做法

1. `keylog.ts`:没有胜也没有逃时再细分:
   - 桥插件 `sample.gameover.open` 为真(桥插件 0.14.3 起有这个字段)→「游戏结束(全灭或倒计时到点):「…」」,种类照旧 `defeat`;
   - 全灭 → 照旧「全灭」;
   - 其余(有人活着、没有游戏结束)→「战斗被剧情结束：「…」(没算胜也没算逃)」,种类**不是** `defeat`(新的种类名，比如 `battle-ended`,写进现有的种类列表和显示文字);
   - 读不到 `gameover` 字段(旧桥插件)时，有人活着就按“被剧情结束”。
2. 机关图上的“走不过去”:
   - 一张图上有会移动的机关(桥插件 `entities` 里能认出的：名字或类型含滑动地板 / 移动平台 / `Gimmick`,以及 `pos.state` 出现过 `Gimmick` 的图;认法写成函数，先认这些，注释写明是推断),这张图上被挡只在本次 `go` 里生效(和任务 83 处理事件格一样:写本次调用的临时禁行，不写进地图记录);
   - 地图记录加载时，这类图上已有的、只见过一次的“走不过去”寻路不用;
   - 把“这张图有移动机关”记进地图记录(新字段),下次进图就知道。
3. 只改上面列的文件。

## 测试

- 战斗结果：被剧情结束 / 游戏结束 / 全灭 / 正常胜 / 逃跑 各一例，文字和种类对;
- 机关图：被挡不写记录、只本次绕开;旧的单次记录寻路不用;普通图照旧记录(回归);
- `npm run check` 全过。
