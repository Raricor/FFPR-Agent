# 任务 69:世界地图的“区域”改用遇敌格子号，`grind` 在世界地图上能用

范围:
- 改 `src/engine/skills/grind.ts`、`src/engine/game.ts`(`refreshCompletion`、`guardLeave`、`isLeaving`)、`src/engine/completion.ts`、`src/engine/encounters.ts`,和对应测试;
- 不改 `../bridge/`、`../agent/`、`../deploy/`;不碰 git;不连笔记本(测试用假桥插件)。
- 这次只有你一个 dsh 任务，可以跑整套 `npm run check`;沙箱跑不了就说，我来跑。

## 起因(11-09 真机，桥插件 0.14.2)

AI 在世界地图上调 `grind(until_bestiary)`,立刻回“读不到当前所在的世界地图区域，不能保证留在本区域，先停下”,世界地图的图鉴只能靠走路碰运气。AI 自己停下来报告了这个问题。

原因：代码按 `encounters.region` 的矩形范围(`start`/`end`)判断“在不在本区域”,而 FF5 世界地图 86 个区域的范围全是 0(11-05 查明),`region` 一直是 null。

但桥插件已经有能用的数据(11-09 真机，人在世界地图 (208,45)):
- `encounters` 回复：`region: null`;`map.scope: "area"`、`map.grids: [169]`(当前所在的遇敌格子号);`map.parties` 是这个格子号的 4 组遇敌(豪猪 350、豪猪×2+大角野牛 350、犰狳×2 230、三种混合 70),完成度行的概率已经是对的。
- `encountgrid`(0.13.8 起):`{"op": "encountgrid", "cells": [[208,45],[213,45],[203,45],[208,50]]}` → `[169, 169, 169, 114]`,一次最多 64 格，读不到的格是 null。

## 要做的

1. **世界地图的“本区域” = 当前格子号**。来源按顺序：`encounters.map.grids` 只有一个值时用它;否则对玩家所在格查 `encountgrid`。完成度状态里的 `region` 用格子号构造(`grid`、显示名“世界地图 · 遇敌区 169”;没有范围就不要 `start`/`end`),欠账的键照旧用 `grid`。
2. **`grind` 留在本区域**:去掉“`region` 没有范围就停下”。挑下一步的候选格时，用 `encountgrid` 批量查候选格的格子号(按地图号 + 格子缓存，同一张地图的格子号不会变)，只走格子号和起点相同的格。查询失败或旧桥插件没有 `encountgrid` 时，才照现在的说法停下。
3. **`isLeaving`(离开检查)**:世界地图上，目标格的格子号和当前格子号不同就算离开(要异步查 `encountgrid`,`guardLeave` 里先查好再判断);查不到格子号时退回现在的做法。
4. 矩形范围的旧逻辑(`insideRegion`)：桥插件以后修好了 `region` 的范围也只当次要依据，有格子号时以格子号为准。不要删 `region` 的解析，别的地方还在读。
5. 测试(假桥插件):① 世界地图 `grind` 能刷：候选格里格子号不同的格不会走进去;② `go` 到另一个格子号的格时被完成度检查拦下(这张区域图鉴没齐)，同一格子号的格不拦;③ 旧桥插件不认 `encountgrid` 时，`grind` 照旧停下说明原因;④ 欠账的键用格子号，回来补齐能自动销掉。
