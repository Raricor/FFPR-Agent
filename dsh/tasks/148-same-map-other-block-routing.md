# 任务 148:同一张图的另一块——经别的地图绕过去

工作目录 `dsh/`。可以改 `src/engine/skills/travel.ts`、`src/engine/route/distance.ts`、`src/engine/route/` 下需要跟着改的文件、`src/engine/regions.ts`(只在要加查询函数时)、`test/`。**不碰** `src/engine/plan/`、`src/engine/game.ts`(任务 145、146 在改)、`src/plugin/`、`src/client/`(147 在改)、`src/engine/prompt.ts`。不碰 `../bridge/`、`../deploy/`、`../agent/`,不碰 git,**不连笔记本**,**不用 docker、不绕开沙箱**。测试数据自己编，不放攻略和游戏原文。

## 起因(11-11 13:13 真机，计划模式，FF5 船舶墓场)

船舶墓场外面(地图 211)被水隔成几块，要穿过沉船(212、213…)才能从一块走到另一块。队伍在 211 (12,23),计划的站点是 211:13,54(一个宝箱)和 211:13,51:
- 路线估算 `route/distance.ts` 的 `sameMapResult` 只在 211 里做格子 BFS,走不通就报“地图 211 里从 (12,23) 走不到 (13,54)(按碰撞缓存)”,整站判 unreachable;
- 真正走路的 `skills/travel.ts` 的 `mapPath` 一开头 `if (from === to) return [];`,同图就不找跨图路线。

跨图寻路早就按(地图，连通块)走了(任务 75/140 的 `nodeKey`、`blockReaches`、`goalCell` 只认落在目标块的入口),只是同图换块这条没接上。模型一连交了好几份计划都撞在这里。

## 做法

1. **`mapPath` 同图换块**:`from === to` 时，若有区域索引，且起点所在块走不到目标格(`blockReaches` 为假),就在(地图，块)图上从起点块搜到目标格所在的块(同一张图的另一个节点),返回经过别的地图的跳转;起点块本来就走得到时照旧返回 `[]`。没有区域索引或起点/目标格不明时照旧。
2. **`sameMapResult`**:格子 BFS 走不通时，用第 1 条的同图换块路线估算(跳数、经过的地图、格数),有路就 ok;都没有才报走不到，原因里写“同图另一块，经别的图也绕不过去”。
3. 走路执行(用 `mapPath` 的那几处)自然得到跨图跳转;核对一下“第一跳就离开当前图”的情况在现有执行里能走(看调用方是否默认同图就直接走格子;是的话在 travel.ts 范围内改)。不改 game.ts。
