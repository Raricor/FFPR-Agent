# 任务 106:首领表在出发前写好——阶段计划里有首领时，在城镇里就让战术官写首领表

工作目录 `dsh/`。可以改 `src/engine/game.ts`、`src/engine/stage/`、`src/plugin/tactician.ts`、`src/plugin/stage-officer.ts`、`src/engine/knowledge/`(只读查询，必要时加一个首领查询)、`src/plugin/config.ts`、`src/plugin/player.ts`、`test/`。不碰 `../bridge/`、`../deploy/`、`../agent/`,不碰 git,**不连笔记本**,**不用 docker、不绕开沙箱**。

## 起因(11-10 真机)

- 02:12 第一次打火力船首领“液态火焰”:首领是踩 271 号图 (15,24) 的事件格自动开打的;开打时 271 还没有首领表，按兜底规则几乎全是普通攻击，**101 秒全灭**。战术官的表在战斗结束后才到。第二次有了表，197 秒险胜。
- 原因：首领前准备(`boss-prep`)要“攻略标了首领、而且人在首领那张图上”才触发;这次战术官以为首领在 104 号图，首领格又是自动开打的，来不及。
- 待办 49、65 也是同一个病根：首领表来得晚。
- 现在有了阶段计划(任务 97 `plan_stage`,事实单里有这一段的首领说明 `bossNotes`、怪物里标了 `boss`),可以在出发前就把首领表写好。

## 做法

1. **出计划时一起写首领表**:`plan_stage` 出计划后，如果事实单里有首领(`monsters` 里 `boss: true`,或 `bossNotes` 非空),就照现有 `boss-prep` 的做法叫战术官写首领表(同步等它写完;首领表很重要，开打前必须有),存成首领所在地图的首领表(现有 `tactics.setBoss`)。
   - 首领在哪张图：知识模块能给就用;给不了(只知道名字)就存成“这一段的首领表”,首领战开打时按敌人名字匹配上(第 2 条)。
2. **开打时按名字找表**:首领战开始时，如果当前地图没有首领表，就在“这一段的首领表”里按敌人名字(或图鉴号)找;找到就直接用，不再等战术官。
3. **路上再确认一次**:到计划路线里首领之前的最后一个存档点 / 回复点时，如果队伍变了(职业、等级明显不同)就让战术官按现在的队伍改一次首领表(照现有 `party-changed`)。
4. 结果文字：`plan_stage` 的结果里写一行“首领「X」的表已经写好”;首领战开始时写“用的是出发前写好的首领表”。
5. 数值进 `Config`(如果有)。

## 测试

- `plan_stage` 有首领 → 战术官(替身)被叫一次，首领表存好;
- 首领战开始、当前图没有表、但“这一段的首领表”里有这个名字 → 直接用，不叫战术官;
- 队伍变了 → 到最后一个存档点时改表;
- 没有首领的一段 → 不叫;
- `npm run check` 全过。
