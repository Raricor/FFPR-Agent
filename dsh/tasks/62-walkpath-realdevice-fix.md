## 起因:11-08 真机标定(FF5 世界地图，徒步，桥插件 0.14.0)

### 现象 1:拐角冲过头，路线结束后人还在走

发了一条 31 格、11 个拐角的闭合路线(`turnLead` 0.6):
- 走了 8 格(2.5 秒)，两个拐角都冲过头(`turns` 两条都是 `ok: false`)，最后在路线外回 `blocked`,`pos` 是 (89,74)。
- **回复之后人又往上走了 4 格**，停在 (89,70)(上面是山)。
- 接着单独发 `hold Left 1000ms`:按住期间人一动不动;松开以后反而**往右**走了一格。
- 把四个方向各自单独按一下、等 600 毫秒再按下一个，之后一切正常。

**原因(我读代码判断的)**:`GameInput.Send` 每次都用 `StateEvent.From(pad)` 读手柄**当前**的状态，改一位再 `QueueEvent`。同一帧里排了两个变化时，第二个事件读到的仍是旧状态(第一个事件要到下一次输入更新才生效):
- `Walker.Press` 拐弯时同一帧先 `Hold(旧键, false)` 再 `Hold(新键, true)` → 事件 1 = {旧=0},事件 2 = {旧=1, 新=1} → 两个事件依次生效后**旧键一直按着**;
- 旧键已不在 `HeldUntil` 里，到期松键管不到它,`stop`(`ReleaseAll`)也管不到;
- 于是拐角变斜按、冲过头;路线结束只松了最后那个键，卡住的键让人继续走;之后的输入全乱。
- 同类情况：`Drain` 里到期松键和新按键碰在同一帧;两条 `hold`(比如逃跑的 L1+R1)碰在同一帧。

### 现象 2:世界地图上读到的格子坐标是整数

- `turns` 里的 `at` 是 [88,78]、[89,74],没有小数。`TryPlayerCellExact` 用的是 `ConvertWorldPositionToCellPosition(player.transform.localPosition)`。
- 所以 `Distance(exact, from) >= LeftCenter` 在 `from` 格上永远是 0,提前换键的条件永远不成立;要等读数变成拐角格才换键。
- 单独按住 `Left` 1.5 秒、开发机每约 30 毫秒读一次 `pos` 的结果(帧号是游戏的 `frame`):

| 毫秒 | 帧 | 格子 | moving |
| --- | --- | --- | --- |
| 401 | 25249 | (89,71) | true(出发) |
| 586 | 25260 | **(88,71)** | **false** |
| 602 | 25261 | (88,71) | true |
| 802 | 25273 | (87,71) | true |
| 1010 | 25279 | (86,71) | true |
| 1102 | 25291 | (85,71) | true |
| 1305 | 25303 | (84,71) | true |

- 结论：读数在**到达那一帧**才变(那一帧 `moving` 是 false),键一直按着时下一帧就开始走下一格。每格约 12 帧(0.2 秒)。往左走也是到达时才变，所以不是对小数坐标取整的效果，更像是游戏自己记的“当前格”。
- 所以等读数变成拐角格再换键，游戏已经按旧键出发了 → 冲过头。

## 要做的

### 1. `GameInput`:每帧只发一个状态事件，按“想要的状态”整个写

- 自己记每个按钮想要的状态(按着 / 松开)，不再从手柄读当前状态改一位。
- `Drain`:先处理到期松键，再把这一帧排队的所有变化合进去，**一帧最多发一个状态事件**，事件里每个已知按钮的位都按“想要的状态”写。
- 同一帧里同一个键先按后放(或者先放后按)，不要互相抵消成“什么都没发生”:按下要至少在一个事件里出现，放开推到下一帧。现在 `keys` 的按和放中间隔着 `Wait(hold)`,一般不在同一帧，但要保证碰上了也不丢。
- `ReleaseAll`(`stop`)和 `Walker` 结束时：所有按钮都写成松开，包括不在 `HeldUntil` 里的。
- `TextEnter` 照旧。

### 2. `Walker`:读数是整数时，在走向拐角的这一步里换键

- 规则(按上面的数据):玩家读数还是 `from`、`moving` 是 true、而且这一步是从 `from` 出发的(在 `from` 上见过 `moving` 为 false 的一帧，或者读数变成 `from` 后已经过了 2 帧以上),就换成出拐角的方向键。这一步已经出发，换键不会改变它;到达拐角那一帧游戏读到的就是新方向。
- 读数确实带小数时(以后在室内图或别的作品可能是)，原来的 `turnLead` 规则照用。按读数是不是整数自动选，不加参数。
- 冲过头回走、`blocked` 的判断看一遍：修好第 1 条之后，回走时不应该再被卡住的键拖着走。
- `turns` 每条加诊断字段(供我真机核对，可以以后删):`mode`(`step` 或 `lead`)、`frame`(换键的帧)、`arriveFrame`(读数变成拐角格的帧)、`moving`(换键时)、`raw`(换键时 `player.transform.localPosition` 的 x、y,看它是不是连续变化)。
