# 任务 83:走不进事件格时不要记成永久的「走不过去」;目标是事件格时要会反复试

工作目录 `dsh/`。只许改 `src/engine/skills/move.ts`、`src/engine/atlas.ts`、`src/engine/nav.ts`、`src/engine/skills/grind.ts`(只读，必要时可改)和 `test/` 下相关文件。另一个任务 82 同时在改 `src/engine/skills/menu.ts`、`shop.ts`、`battle.ts`、`game.ts`:不要碰这些文件;如果 `npm run check` 失败在那些文件上，在回报里说明，不要去修。不碰 git,不连笔记本。

## 起因(11-09、11-10 真机，火力船地图 265)

- 265 南侧一排四个事件格(`!`):(9,16)、(11,16)、(13,16)、(15,16),名字「通路に流される1」到「4」(通风口)。踩进去会触发事件、掉到地图 261(比如 (13,16) → 261 (13,26))。中间夹着的 (10,16)、(12,16)、(14,16) 是普通地面。
- AI 用 `go` 走进这些格子总失败，地图记录 `atlas-ff5.json` 的 265 里记下了 3 条「走不过去」:(14,16)→(13,16)、(12,16)→(13,16)、(14,16)→(15,16)。
- 但 `grind` 的游走进去过两次:00:07:50 从 (10,16) 往左进了 (9,16);00:10:03 从 (12,16) 往右进了 (13,16)(后一次正是上面记成「走不过去」的那一步)。两次都是 `grind` 报 `interrupted:state:Event`,随后换图到 261。
- Claude 11-10 0:40 真机实验(游戏没有别的操作):
  - `walkpath` 路线 (14,13)→…→(14,16)→(13,16):到 (14,16) 后回 `blocked`,`index` 3,没进去;
  - 在 (14,16) 用 `hold` 按住 `左` 20 秒：人一格没动;
  - 在 (12,16) 用 `hold` 按住 `右` 22 秒：人一格没动;
  - 面朝 (13,16) 按确认：没反应。
  - 所以进不进得去取决于某种还没查清的条件(时机、走过来的方式等),**同一步有时能走、有时不能**。
- AI 把这当成工具毛病，在笔记里写「go 走不上事件格，用 grind 乱走去踩」。

## 做法

1. **先查清 `grind` 的一步和 `walkpath` 有什么不同**:读 `grind.ts` 的 `stepTo` 等，写清楚它怎么按键(单次点按 `keys`?先转向再走?每步之间停多久?)。回报里写出来。
2. **不要把事件格记成墙**:
   - 一步的目标格是带名字的事件格(实体类型是事件、或 `look_around` 里 `!` 标出的触发点、或名字含「流される」),被挡住时不写「走不过去」记录;
   - 地图记录加载时，已有的、目标格是这类事件格的「走不过去」记录不再当作阻挡(可以留着，但寻路不用);
   - 判断「是不是事件格」需要实体信息：地图记录或碰撞缓存里没有的话，用当前图 `entities` 的结果;拿不到就照旧。
3. **`go` 的目标正好是事件格时**:
   - 走到它旁边的一格，然后按第 1 条查到的 `grind` 那种方式试着踩进去;
   - 每个能站的相邻格都试，每格试几次，中间等一会儿(次数和等待进 `Config`,默认先 3 次、1 秒);
   - 进去了(状态变 `Event` 或换图)就照常交给剧情/换图处理;
   - 都不行就照实说：「(13,16) 是事件格「通路に流される3」,从 (12,16)、(14,16) 各试了 3 次都被游戏挡住，没记成走不过去」,不要说「走不过去」。
4. 不改桥插件。

- 加载含旧「走不过去」(目标是事件格)记录的地图记录，寻路不再把它当墙。
