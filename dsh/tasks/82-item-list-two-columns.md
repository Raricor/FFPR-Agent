# 任务 82:地图菜单道具列表是两列的，光标定位要用左右键

工作目录 `dsh/`。只许改 `src/engine/skills/menu.ts`、`src/engine/skills/shop.ts`、`src/engine/skills/battle.ts`(只为接诊断回调)、`src/engine/game.ts`(只为接诊断回调)和 `test/` 下相关文件。另一个任务 83 同时在改 `src/engine/skills/move.ts`、`src/engine/atlas.ts`、`src/engine/nav.ts`:不要碰这些文件;如果 `npm run check` 失败在那些文件上，在回报里说明，不要去修。不碰 git,不连笔记本(测试用 `test/fake-pilot.ts`、`test/fake-item-menu.ts` 这类替身)。

## 起因(11-10 真机)

- 战后整备(`battle.patchUp`)两次想用眼药治黑暗，都报「光标没能移到「眼药」」;AI 自己的 `use_item` 以前也常报同样的话(11-02 不死鸟之尾、11-08 恢复药)。
- 任务 77 判断是「`listCursor` 是可见窗口内的行号」,改成优先看 `selected`。真机核对后,**根因不是这个**:
  - 地图菜单「道具 → 使用」的列表是**两列**的网格;
  - 真机记录(31 行的列表):
    - `下` 每次 +2:listCursor 0→2→4→…→30→0(到底回到开头);
    - `上` 每次 −2:1→29(到顶绕回);
    - `右` +1、会换行:0→1→2;
    - `左` −1:4→3;
  - `listCursor` 在这里就是整表的序号(0..30),不是窗口内的行号;
  - `selected` 一直等于光标所在那一行的名字，可靠。
- 现有 `steerItemList` 只按上下键：目标在奇数号(右列)时永远到不了，按到 120 次放弃。目标在偶数号时又能成功，所以时好时坏。
- 战后整备这条路径没有接上任务 77 的诊断回调，失败时活动日志里没有光标记录。

## 做法

1. 改 `steerItemList`(或抽成一个通用的「网格列表定位」):
   - 当前位置以 `selected` 在 `rows` 里的序号为准，读不到再用 `listCursor`;
   - 差 ≥ 2 按 `下`/`上`,差 1 按 `右`/`左`;按后读一次再算，不靠数按了几次;
   - 列数不写死：第一次按 `下`/`上` 后，用序号变化量推出列数(默认 2);
   - 卡住检测保留(连续几次 `selected` 和 `listCursor` 都不变就停);
   - 绕回(到底回到开头)不能让循环走错方向：每次都按「当前 → 目标」的差决定按哪个键。
2. 商店的**卖出**列表(`shop.ts`)很可能也是同样的两列网格(待办 55:卖东西从来没成功过)。卖出定位改用同一个函数。真机没核对过：注释里写明是推断，等 Claude 真机卖一次。
3. 战后整备用道具的路径接上诊断回调，失败时和 `use_item` 一样把道具行、光标、按键写进活动日志。
4. 战斗里用道具的列表不要动(战斗里用道具在真机上是好的)。

## 测试

- 改 `test/fake-item-menu.ts`(或新建)让它按上面的真机规则模拟：下/上 ±2 并绕回，右/左 ±1 并换行，`selected` 跟着走。
- 测：目标在左列、右列、最后一行(奇数总数)、要绕回的情况都能一次到达;按键序列最短或接近最短;卡住时会停。
- 卖出列表用同一个替身测一次。
- `npm run check` 全部通过。
