# 任务 144:计划里的“买东西”由代码自己去店里买

工作目录 `dsh/`。可以改 `src/engine/plan/execute.ts`、`src/engine/plan/game-ports.ts`、`src/engine/plan/validate.ts`(只为买东西的检查和提示)、`src/engine/game.ts`(只加端口)、`test/`。**不改** `src/engine/plan/types.ts`,不碰 `src/engine/skills/travel.ts`、`src/engine/regions.ts`、`src/engine/nav.ts`(任务 143 同时在改)、`src/plugin/`、`src/engine/prompt.ts`,不碰 `../bridge/`、`../deploy/`、`../agent/`,不碰 git,**不连笔记本**,**不用 docker、不绕开沙箱**。测试数据自己编。

## 起因(11-11 12:34 真机，计划模式)

模型的计划 `prep.buy` 写了 Fire/Blizzard/Thunder/Cure/Poisona。第一次人在风之神殿里，执行器记「没买成：不在商店」;后来模型专门写了一份计划把人带进图尔村魔法店(地图 38 (7,10)),下一份计划的准备阶段照样「没买成：不在商店，没买「Fire」…」——执行器说的“在商店”是商店菜单已经打开，而人只是站在店里。

## 做法

1. **买东西变成执行器自己会做的事**:`prep.buy` 里的每样东西：
   - 找卖它的店：知识模块/游戏文件的商店数据(商品三语名、店在哪张图、店员 NPC 的格子;看 `shop`/`shop_gear` 工具和任务 142 的商店索引怎么取);优先这一段路上/出发点附近的店;
   - 走到店员面前、面朝他按确认打开商店菜单，用现有的买东西能力(`buy` 的引擎实现)买到数量，关菜单;同一家店的东西一次买完;
   - 钱不够就按计划顺序买到钱用完，记一条“钱不够没买：…”(不算例外);整段找不到卖的店才记“这段路上没有店卖：…”。
2. **顺序**:准备阶段先换职业、装备，再按店分组去买，买完回到计划的第一站;如果店不在出发点附近而在路上，就在路过那个城镇时插一站去买(由执行器插，不需要模型写)。
3. 计划检查(`validate.ts`)对买东西的提示同步：写明“代码会去 X 店买”,买不到的照旧报问题(142 的规则)。
4. 测试：替身端口——人在店里但菜单没开 → 走到店员、开菜单、买到;两家店分组;钱不够;路上插站;`npm run check` 全过。
