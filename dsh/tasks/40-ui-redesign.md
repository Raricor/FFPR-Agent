# 任务 40:dsh 界面重做：只显示开着的那一作，三层策略分开展示

范围:
- 只改 `src/`(主要是 `src/client/index.ts`、`src/plugin/` 的路由和视图、`src/engine/` 里的视图数据和记录)和 `test/`;
- 不改 `src/engine/skills/battle.ts` 的出招逻辑、`src/engine/strategy/` 的语言规格(可以调用它);
- 不改 `package.json`、`tasks/`、`lib/`、`../agent/`、`../bridge/`、`../deploy/`;
- 不碰 git;不运行 `npm run build`、`scripts/web.sh`、`scripts/ask.mjs`;不连笔记本。
- **重型检查排队**:`flock /tmp/ffpr-heavy.lock npm run check`。
- **分段做**，每段做完跑一遍检查，中途断了能从已完成的部分接着做：
  1. 当前作品 + 总控;
  2. ① 玩家;
  3. ② 战术官;
  4. ③ 战斗 + 成就 + 统一样式。
- 前端规矩照 `dsh/CLAUDE.md`:一个文件，文字由服务端算好，前端只排版;`localStorage` 包 try/catch。

## 起因(用户 11-03)

- **一次只开一作**，界面却还是六作并列：总控是六张卡片，成就、策略标签都有 FF1–FF6 的选择框。用户要：**只显示开着的那一作，由运行的游戏决定。**
- **三层策略要分开展示。** 现在「FFPR 策略」一个标签从上到下塞着这些：战斗中、战斗记录、当前地图的规则表、敌人、遇敌表、最近的战斗、其他地图的策略、首领表，哪一层的东西都看不出来。用户觉得现在的界面不行。

## 定下来的布局(用户 11-03 选的)

```
左侧「FFPR 总控」    只看当前那一作的一张大卡片 + 这一作的日志
右侧四个标签          「① 玩家」「② 战术官」「③ 战斗」「成就」
```

## 要做的

### 1. 当前作品 + 总控

- **新路由 `GET /api/ffpr/current`**:返回当前作品，以及它是不是在运行。决定办法:
  1. 检测结果(`detect.ts` 的缓存，`peekDetection`,不要为此多跑 SSH)正好开着一作：就是它;
  2. 否则：最近启动过引擎的那一作;
  3. 再否则：活动日志最近有记录的那一作。
- **前端**：所有面板都按这个作品显示，**去掉 FF1–FF6 的选择框**。当前作品变了，就自动切过去。
- **左侧「FFPR 总控」**改成一张大卡片:
  - 标题：作品名 + 状态(运行中 / 没在运行);
  - 桥插件：版本、连着没有、ATB(桥插件 0.13 的 `sample.battle.atb`,`wait` 写「等待」、`active` 写「实时」);
  - 地点：地图号和名字;
  - 队伍每人一行：名字、职业、等级、HP 条(数字 + 条)、MP;
  - 金钱、存档次数;
  - AI 正在做什么(正在跑的工具和已经跑了多久);
  - 下面是这一作的日志(现在总控页的日志，只留这一作)。
- 没在运行时：卡片灰一点，写「没在运行」,数据显示最后知道的样子，并标上时间。

### 2. ① 玩家(第一层)

- **数据来源**:玩家插件监听 `session/event`(`@deepseek-ai/dsh-session` 的 `lib/types/index.d.ts`;预设里的插件只会收到自己那些会话的事件)。
  - `user/message` 里 `source.kind == "user"` 的，是用户或 Claude 发来的消息;
  - `assistant/message` 里的文字(不含 reasoning),是 AI 说了什么、打算做什么;
  - `tool/call`、`tool/result` 是它做了什么。
- 每作留最近 100 条，存 `.deps/ds/player-<作品>.jsonl`,网页重启后还在。路径照 `config.ts` 里别的文件那样推算。
- **标签里显示**:
  - **目标**：最近一条用户 / Claude 消息;
  - **现在**:AI 最近一段文字，截短;
  - **笔记**:`game.notes` 全部;
  - **最近的决定**：最近 15 次工具调用，每条一行「时间 工具 参数摘要 → 结果第一行」，上面一行用灰字写它调用前说的那句话(有的话);
  - **收到的消息**：所有用户 / Claude 消息，带时间，标题写「收到的消息(N 条)」。

### 3. ② 战术官(第二层)

- **把战术官的输出存下来**：现在走法说明和建议只放在内存里(`game.ts` 的 `tacticianInfoByMap`),网页一重启就没了。
  - 改成跟规则表一起存进 `tactics-<作品>.json` 的地图条目:`walkerNotes`、`askUp`、`writtenAt`;
  - 首领表也按地图存进去(`boss`:规则表、结果、中途重写);
  - 旧文件没有这些字段时照常读。
- **记下每次叫战术官**：时间、地图、原因(触发类型和说明)、交回了几套表、检查出的问题、走法说明的第一句。存 `.deps/ds/tactician-<作品>.jsonl`。
- **标签里显示**:
  - **当前地图**：走法说明、建议;
  - **规则表**：每套一块，块里每个角色一张小卡片。规则用 `src/engine/strategy/` 的 `fromLegacy` 转成 2.0,再用 `describe` 翻成中文，一条一行，旁边写这条在战斗记录里触发了几次;
    - 最近的战斗里，这条规则因为做不到被跳过的，在旁边标橙，写原因。例如「法利斯 黑魔法:火炎 → 跳过 2 次：没有这个指令(现在是武僧)」;
    - 当前在用的那一套标出来;每套的战绩(用了几次、赢 / 吃力 / 全灭);
  - **首领**：这张图存下的首领表(同样翻成中文)、结果、中途重写了几次和原因;
  - **叫过战术官**：最近的记录，每条一行;
  - **其他地图**：折叠着，点开再看。

### 4. ③ 战斗(第三层)、成就、统一样式

- 把任务 36 的「战斗中」「战斗记录」移到这个标签。
- **接上桥插件的出招事件**:
  - 引擎从推送流里收 `battle.act`、`battle.hit`(桥插件 0.13 新加的;字段看 `../bridge/README.md` 的事件表);
  - 记进正在打的那场战斗记录的 `events`;
  - 「战斗中」的回合列表里，按时间穿插敌人的出招，例如「00:12 犰狳 → 撞击 → 巴兹 -3」;反击标出来。
- **规则命中统计**：按地图和第几套表，汇总最近的战斗：每条规则触发几次、跳过几次。
- **结果改成中文**：赢 / 吃力 / 全灭 / 超时，不要显示 `ok`。
- **战斗记录不依赖引擎**：引擎没启动时也从 `.deps/ds/battles-<作品>.jsonl` 读出来显示。
- **成就标签**：跟着当前作品走，去掉选择框，其余不变。
- **统一样式**：写几个共用的小函数：卡片、小标题、HP 条、标签色块(赢绿、吃力橙、全灭红、跳过橙、兜底灰)，四个标签和总控都用它们。不要每处各写一套 style。
- **空的状态都要有一句话**：没开游戏、引擎没启动、还没有战斗、还没叫过战术官……
