## 起因(11-09 真机，火力船)

AI 在火力船连着两轮来回跑：地图 255“机房”在碰撞数据里是**两块互不连通的区域**(我抓了夹具 `test/fixtures/nav/map255-firepowered-ship.json`,一层 `UpperCollision`):
- 北半：人所在的 (6,7) 一带，出口 (6,6)→635、(10,16)→634(都是升降机);
- 南半：出口 (19,20)→258、(6,26)→253;从 258 进来落在 (19,21),从 253 的 (5,16) 进来落在 (6,25)。

任务 70 的绕路已经生效：它说“目标 (6,26) 和你现在所在的区域不连通，能走到目标的落点有 (19,21)、(6,25)”,还试了经 634/635 绕，但地图记录里升降机的出口都写着 → 255,于是绕回北半。

**升降机是怎么坐的**(会话日志里 AI 实际做的):进升降机那张图(257、634、635、260 都是“火力船 升降机”),站在 (4,6) 面朝左按确认(`interact` (3,6)),电梯动了，**地图号变了**:257 → 634、635 → 260。也就是同一部电梯停在不同楼层是不同的地图号。地图记录里 257、634 等只记了走出门的出口(`(5,9)` → 253 / 255 / 261),没有“坐一趟”这种不经过出口的地图变化，所以规划不出:

255 北 →(10,16)→ 634 —坐一趟→ 257 →(5,9)→ 253 →(5,16)→ 255 南 (6,25)

## 要做的

1. **记录“坐一趟”**:`interact`(以及任何不是走进出口格造成的地图变化)之后，如果地图号变了，就在地图记录里记一条边：从哪张图、站在哪格、按的哪个方向/哪一格，到哪张图、落在哪格。已经有的“调查后跳 (7,8)→(10,6)”这类同图跳转的记法可以参考;这是跨图的。重复坐只更新，不重复记。
2. **规划用上它**:`travel` 跨图规划时，这种边和出口一样可走，执行时走到那一格、面朝记下的方向按确认，等地图号变成记下的目标;到了别的图(电梯停在别层)就照现有逻辑从实际到的地方重新规划。
3. **把这次已经发生过的几趟补进地图记录的种子**(和 11-05 补 `atlas-save` 一样，从会话日志找):至少 257 → 634、635 → 260;反方向(634 → 257、260 → 635)如果日志里有也补。在回报里列出补了哪些、从哪条日志来的。真实的 `../.deps/ds/atlas-ff5.json` **不要直接改**,写一个能重放的小函数或脚本，我审完自己跑。
4. 测试：用 255 夹具 + 一份最小地图记录(253、255、257、258、634、635 的出口和上面两条“坐一趟”边):从 255 北 (6,7) `go` 到 (6,26) 能规划出经 634 → 257 → 253 → 255 南的路线;没有“坐一趟”边时退回任务 70 的说明。
