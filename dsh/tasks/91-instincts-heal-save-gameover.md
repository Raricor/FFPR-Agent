# 任务 91:本能层补四样——战后补血补 MP、倒计时里的存档保护、游戏结束自动回 20 号档、等待中卡死就返回

工作目录 `dsh/`。可以改 `src/engine/`(含 `skills/`)、`src/plugin/config.ts`、`src/plugin/player.ts`、`test/`。不碰 `../bridge/`、`../deploy/`、`../agent/`,不碰 git,**不连笔记本**(测试全用替身桥 / 替身 pilot)。

**不许用 docker**,也不许用任何办法绕开 dsh 的沙箱(11-10 有任务用 docker 把宿主机目录挂进容器编译，这是越权)。沙箱里 `npm` 跑不起来时，照以前的办法把代码拷到 `/tmp` 跑 `npm run check`,回报里写明。

## 起因

用户 11-10 的方向：本能层不够，寻路、战斗这些都要放进本能(代码),AI 只在阶段开始和真正的决策点出场。这次补四样：

1. **补血补 MP**:用户指出队伍有白魔法(治疗、救疗)却没怎么用;11-10 打液态火焰前四人都没满血(498/691、341/498、457/507、351/507),第一次 101 秒全灭。现在战后整备(`battle.patchUp`)只治状态、救倒下的，不补血。
2. **倒计时里的存档保护**:11-10 卡纳克城逃脱(10 分钟倒计时)里 AI 连存两次(第 18、19 次),每存一次能用的时间少半分钟;只能写 20 号位，存到只剩一两分钟就成了逃不出去的死档。
3. **游戏结束自动回 20 号档**(用户 11-10 定的):全灭或倒计时到点后，画面是「要从最新的保存数据开始吗？是/否」(默认“是”,读游戏的自动保存);选“否”后是「返回标题画面。可以吗？是/否」(默认“否”)。用户定：**不读自动保存，回标题读 20 号位**。11-10 这两个画面让 `advance_story` 一直等、整个卡住;Claude 手动处理时还因为盲按读错过一次档。桥插件 0.14.3 已经能认:`sample.gameover = {open, prompt: "continue"|"to-title"|null, cursor: 0|1|null, autosave}`(`cursor` 0 是“是”、1 是“否”)。
4. **等待中卡死**:`advance_story` 这类等待的工具，画面不动时会一直等到超时(`story` 等 10 分钟)。

## 做法

1. **补血补 MP**(在 `battle.patchUp` 的流程里，或者紧跟它，地图上做):
   - 战后有人 HP 低于阈值(`Config`,默认 70%)就补;先用魔法：能放的人(会这个魔法、MP 够)放治疗/救疗，按缺口选最省 MP 的;施法者保留一部分 MP(`Config`,默认最大 MP 的 30%),只有在存档点、旅店附近或首领前才可以用到底;
   - 没有魔法可用、或者 MP 只剩保留量时，HP 低于更低的阈值(`Config`,默认 40%)才用恢复药类道具(省道具);
   - **首领前和存档点补满**:`boss-prep` 触发时、站在存档点时，补到 95% 以上，MP 不够且包里有帐篷/小屋就在存档点用掉(帐篷只能在存档点用;用道具走现有 `use_item`,任务 82 修过的网格定位);
   - 地图上施法用现有 `cast` 的流程;结果里写一行用了什么、谁补到多少。
2. **倒计时里的存档保护**:`timer.active` 为真时，`save_game` 在剩余秒数少于 `Config`(默认 300)时拒绝，回一句「倒计时只剩 X 秒，存档会把这段时间固定在 20 号位;剩不到 300 秒不存」;旧桥插件没有 `timer` 字段时照旧存。
3. **游戏结束自动回 20 号档**:
   - 每次工具调用结束前(以及第 4 条的等待里),如果 `sample.gameover.open` 为真，就按下面的顺序处理，**每按一键前都读 `gameover` 核对 `prompt` 和 `cursor`,不对就停下报告，绝不盲按**:
     1. `prompt=continue`:把光标移到“否”(`cursor` 变成 1)→ 确认;
     2. `prompt=to-title`:把光标移到“是”(`cursor` 变成 0)→ 确认;
     3. 等标题画面：用桥插件的 `title` 查询，没打开时按一次确认过片头(只在 `title.open` 为假、且 `gameover.open` 也为假时按);打开后把光标移到 `LoadGame`(按 `title.commands` 核对)→ 确认;
     4. 读档列表(`saveui` 查询的 `slots`/`cursor`):把光标移到 20 号位，核对后确认，再按确认画面上的“是”;做法照现有读档的经验:`.deps/tmp/load-slot.py` 是 Python 版参考(在仓库外层 `.deps/tmp/`,读不到就按这里写的步骤做);
     5. 等 `pos.state` 变 `Player`,工具结果写「游戏结束了(倒计时到点/全灭),已回标题读 20 号位第 N 次存档，现在在地图 X (x,y)」。
   - 任何一步失败就停下，照实报告当时的画面状态，不继续按。
   - 这个流程做成一个独立函数，单元测试全覆盖;旧桥插件没有 `gameover` 字段时什么也不做。
4. **等待中卡死就返回**:`advance_story`(以及 `route`、`go` 里等剧情的地方)等待时，每隔几秒读一次 `pos`/`sample`:
   - `gameover.open` → 中止等待(用现有的取消写 `.abort` 的办法),走第 3 条;
   - 状态、对话行、场景超过 `Config`(默认 60 秒)都没变化 → 中止等待，返回「画面 60 秒没有变化：状态 X,对话「…」」,不再等满 10 分钟。

## 测试

- 补血：战后一人 60% → 用治疗补到阈值以上;MP 只剩保留量 → 不施法，HP 低于 40% 才用药;首领前补满、存档点用帐篷;
- 存档保护：倒计时剩 200 秒拒绝、剩 400 秒照存、没有 `timer` 照存;
- 游戏结束：替身桥按真机的两个弹窗和标题、读档列表走完整个流程，按键序列和每步核对都对;光标读数不对时停下、不按;
- 等待卡死：画面 60 秒不变返回;等待中出现游戏结束弹窗 → 转第 3 条;
- `npm run check` 全部通过。
