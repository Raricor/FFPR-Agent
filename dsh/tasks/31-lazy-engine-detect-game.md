# 任务 31:网页启动时不连笔记本，按开着的作品启动引擎

范围:
- 只改 `src/` 和 `test/`;
- 不改 `package.json`、`package-lock.json`、`cordis.patch.yml`、`scripts/`、`tasks/`、`lib/`、`../agent/`、`../deploy/`;
- 不碰 git;
- **不运行 `npm run build`**:Claude 这时正用 `lib/` 里现有的版本跑网页;
- **不运行 `scripts/web.sh`、`scripts/ask.mjs`,也不运行任何会连笔记本的东西。** 笔记本现在开着、在局域网上，误连就是真连上了。测试一律用 `test/fake-ssh.mjs` 和假桥插件。

## 起因

1. **网页一启动就连笔记本。**
   - `src/index.ts` 的 `apply()` 里，六个玩家预设各自调用 `startEngine()`;
   - 每个引擎先经 SSH 取探针日志(`followEvents` → `fetchProbeLogs`),再由 `Watcher` 每 5 秒连一次自己的桥插件;
   - 结果是：重启网页 = 马上 6 次 SSH,外加六个桥插件端口不停重连。11-02 就因为这样，在用户没同意的时候连上了笔记本。
2. **用户 11-02 定了：一次只开一作**，引擎按笔记本上开着的作品启动。启动脚本那边由另一个任务改，以后同一时间最多只有一作在运行。

## 要做的

### 1. 查笔记本上开着哪几作(engine 层)

新函数，比如 `src/engine/running.ts` 的 `runningGames(laptop, signal)`:
- 一次 `runPs`,返回正在运行的作品键数组(`["ff5"]`、`[]`、`["ff3","ff5"]`),按 `ff1`→`ff6` 排序;
- PowerShell 那边 `Import-Module` 已部署的 `FfprCommon.psm1`,写法照 `fetchProbeLogs`;
  - 对六作逐个调用已有的 `Find-GameDir` 和 `Test-GameRunning`。另一个任务会在笔记本那边加 `Get-RunningGames`,但还没部署，这里不用它;
  - 没装的作品(`Find-GameDir` 抛错)当作没开;
  - 输出一行 JSON;
- 开发机这边按 `unknown` 解析、检查，不认识的键丢掉;输出不是合法 JSON 就抛中文错误。

### 2. 共享的检测结果(plugin 层)

- 六个玩家预设和根上的面板条目共用一份检测结果。像 `registry.ts` 那样放在 `globalThis` 上，并在注释里说明原因;
- 同一时刻只跑一次 SSH,并发的调用者等同一个结果;
- 结果缓存 `detectCacheMs` 毫秒，放进插件 `Config`,默认 10000;
- 返回成功(`running` 数组)或失败(中文原因)，不往外抛。

### 3. 引擎改成用到时才启动

- `apply()` 里不再调用 `startEngine()`,改成登记一个“引擎槽”:
  - 第一次要用时才启动;
  - 同时有几处要用，只启动一次;
  - 启动失败，下次再要时重试;
  - 插件卸载时，已启动的引擎照现在的做法停掉。
- **加载插件、建 Agent 都不能连笔记本**:不跑 SSH,不连桥插件。只读本地文件(`laptop.env`、`secrets.env`、笔记、活动日志)可以。
  - 工具定义、人设提示词、笔记和战术官的提示词段，现在在建 Agent 时就要用到引擎。改成不依赖已启动的引擎，或者在没启动时给空内容。
- `registry.ts`:
  - `engineFor(game)` 照旧，只返回**已启动**的引擎;
  - 另外让面板能找到槽、启动它。
- `src/plugin/commands.ts` 的 `/ach`(只有 FF5 注册)也改成经槽取引擎。

### 4. 每轮第一步先看开着的是哪一作

在 `installPlayer` 的 `agent/pre-step` 里，第 1 步先查检测结果:

| 检测结果 | 做法 |
| --- | --- |
| 正好是本预设的作品 | 启动引擎(已启动就直接用)，然后照现在的流程走：等桥插件、`ensureAgent`、开局消息 |
| 一作都没开 | 不启动引擎 |
| 开着别的作品 | 不启动引擎 |
| 开着两作以上 | 不启动引擎 |
| 检测失败 | 不启动引擎 |

不启动引擎的四种情况，都**照常进入这一步，但不加开局消息，改加一条说明**:
- 说明讲清是哪种情况，例如：「笔记本上开着的是 FF3,这个会话玩的是 FF5。」;
- 还要告诉模型：这一轮**不要调用游戏工具**，直接用一两句话把情况转告用户，并说怎么办。比如“新建一个「FF3 玩家」会话，或者在笔记本上关掉 FF3、开 FF5”；没开游戏时就说“先在笔记本上启动 FF5”；
- 消息照现在的 `withOpening` 那样加，有自己的 source。

为什么不用 `{ kind: "reject" }`:dsh-agent 的类型注释写着，被拒的那一步领走的消息“就此结束”，用户看不到任何说明。

- 第 2 步以后：引擎没启动就不等桥插件，其余照旧。
- 引擎没启动时调用游戏工具：返回一句中文「工具出错:…」，说明原因(例如 FF5 没在运行)，不抛到 dsh。

### 5. 总控页跟着开着的作品走

`src/plugin/overview.ts` 的路由每次被请求时:
- 先看检测结果(有缓存，最多 `detectCacheMs` 查一次);
- 正好开着一作、它的引擎还没启动：在后台启动它。不阻塞这次回复，失败记日志;
- 卡片上，没启动引擎的作品，`linkText` 写清楚：检测到没开就写「没开」，还没查过或查失败就写「还没启动」。前端不用改。
- `src/plugin/panel.ts` 的成就、策略路由，引擎没启动时照现在的写法回错误，提示语改成「FF5 没在运行」这类。

### 6. `src/engine/laptop.ts` 的 `launch()`

笔记本那边改完以后，状态文件的 `state` 可能是 `refused`,带 `note`(例如「FF3 还开着，一次只开一作，先关掉它」)。
- `launch()` 读到 `refused` 时抛错，消息用 `note`;
- 其他照旧。
