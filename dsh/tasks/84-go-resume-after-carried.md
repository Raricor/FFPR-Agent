# 任务 84:`go` 中途被带走以后接着走向原目标，不交回给 AI

工作目录 `dsh/`。只许改 `src/engine/skills/move.ts`、`src/engine/skills/travel.ts`、`src/engine/game.ts`(只为传参和结果文字)、`src/plugin/config.ts`、`src/plugin/player.ts`(只为把数值接进 `Config`)和 `test/` 下相关文件。不碰 `../bridge/`、`../deploy/`、`../agent/`,不碰 git,不连真的笔记本。

## 起因

用户 11-10 指出：掉进陷阱、刷怪时都会离开路径，要有算法回到该去的地方。整体方案(路线单存盘、偏离分类、什么时候叫 AI)以后做;这个任务先做 `go` 自己能做的一小步。

现在的 `go`(`navigate` / `travelToMap`)遇到偏离时:
- 遇敌打完、位置变了：从当前位置重算，接着走(好的，不要动);
- 电梯把人送到意外的地方：跨图规划里从实际位置重算(好的);
- **踩到传送带被带走、掉下去**(同一张图里):记下这条边(`state.link(... "传送带" / 掉落 ...)`),然后返回 `[false, "踩到传送带 …,被带到 …"]`,这次 `go` 就结束了，AI 得自己再调一次;
- **同图的 `go` 中途换了图**(掉到别的图、被剧情送走):返回 `[true, "进入了地图 X,现在在 …"]`,当成走完了，其实目标根本没到。

## 做法

1. **被带走以后接着走**:同一张图里被传送带、掉落、陷阱带走，记下边以后，从落点重新规划到**原来的目标**,接着走。
2. **同图目标中途换了图**:
   - 不再当成“到达”;
   - 新图到原目标所在图有路(用跨图规划 `mapPath` 那一套)就接着走回去;
   - 没有路就停下，照实说：「原目标在地图 A (x,y),中途在 (x,y) 掉到/被带到地图 B (x,y),按地图记录回不去」。
3. **防止陷阱循环**:
   - 一次 `go` 里，同一处(同一个起点格 → 同一个落点)被带走 2 次就停下，报告这一处;
   - 一次 `go` 里被带走的总次数上限(默认 4);
   - 两个数进 `Config`。
4. **结果文字**:每次被带走写一行，例如「在 (13,25) 踩到传送带，被带到 (13,22),从这里接着走」,最后照常写到达或停下的原因。
5. 被带走的边照旧记进地图记录(现有逻辑不变)。
6. 计划内要踩上去的格子(目标本身就是传送带/事件格，比如任务 83 处理的事件格)不算偏离。

## 测试

用替身桥 / 替身 pilot:
- 同图被传送带带走一次 → 接着走到原目标，结果里有被带走的那一行;
- 同一处被带走两次 → 停下，报告这一处;
- 同图 `go` 中途掉到别的图，地图记录里有回去的路 → 走回去到原目标;没有路 → 停下，文字如上，不说“进入了地图”;
- 遇敌打完接着走的旧行为不变(回归);
- `npm run check` 全部通过。
