# 任务 26:FF5 也改成新游戏、写 20 号位

开始前先读 `dsh/CLAUDE.md`。

范围:
- 只改 `dsh/src`、`dsh/test`,以及 `dsh/CLAUDE.md` 里讲存档位的那一行;
- 不碰 git,不重启网页。

## 起因

用户 10-29 定的:六作全部从新游戏开始，存档都只写 **20 号位**。FF5 也一样，不再读写 3 号档(那是用户自己的档)。

## 要改的

1. **默认存档位**:`gameDefaults`(`src/plugin/config.ts`)和 `saveSlotFor`(`src/engine/prompt.ts`)对六作都返回 20。注释写明日期和原因。
2. **FF5 的 `save_game` 工具说明**:现在写死了「存档到 3 号存档位」(`prompt.ts` 653 行附近)。改成用传进来的 `saveSlot`,像五作那样。
3. **FF5 的玩家提示词**:`SYSTEM_PROMPT_FF5` 里凡是讲 3 号位、或者讲「读档接着玩」的地方，改成新游戏、20 号位。
   - 再加一句，和五作的那句意思一样:「游戏已经开好新游戏、过了起名，从现在的位置开始玩;第一次能存档时就用 save_game 存档。」
   - FF5 提示词别的部分不动。
4. **对照测试**:FF5 提示词原来要求和旧常量一字不差。fixture 只改上面这几处，其余仍须一字不差;在测试里写明改了哪几处、为什么。
5. **`dsh/CLAUDE.md`**:「存档位」那行改成「六作都从新游戏开始，只写 20 号位(用户 10-29 定的);别的存档位不读不写」。

## 测试

- 六作的默认存档位都是 20。
- FF5 的 `save_game` 说明里写的是 20 号。
- FF5 存档时，光标不在 20 号位就不按确定，照现有的五作测试写。
- `npm run check` 全过。
