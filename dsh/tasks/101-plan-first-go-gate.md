# 任务 101:有阶段计划时，这一段里用 `go` 走坐标要硬拦——改用 `route` 接着走计划

工作目录 `dsh/`。可以改 `src/engine/game.ts`、`src/engine/prompt.ts`、`src/engine/stage/`(只为读当前计划，`types.ts` 不改)、`src/engine/metrics.ts`(第 4 条)、`src/plugin/config.ts`、`src/plugin/player.ts`、`test/`。不碰 `src/engine/scout/`、`src/engine/skills/load.ts`(任务 102 在建)、`src/engine/skills/gambit.ts`、`skills/battle.ts`、`strategy/`(任务 104 在改)。不碰 git,**不连笔记本**,**不用 docker、不绕开沙箱**。

## 起因

用户 11-10:`go` 调得太多(新局 585 次，60% 是同一张图里走坐标;凌晨卡纳克城逃脱 26 步一步一步走，倒计时到点)。现在有了阶段计划(任务 97 `plan_stage`,存在 `.deps/ds/stage-<game>.json`)和 `route`(任务 89/100,一段路一口气走完)。用户同意：**有阶段计划时，这一段里 `go` 走坐标要硬拦**,让 AI 改用 `route` 接着走计划，或者写理由放行。

## 做法

1. **什么时候拦**:有状态为“进行中”的阶段计划，人在这一段里(目的地区域，或计划路线经过的地图),AI 调 `go` 且 `to` 是坐标(`"x,y"`、`[x,y]`、`"地图号:x,y"`)。
2. **不拦的例外**(这些本来就只能用坐标):
   - 目标格是没有名字的隐藏道具格、事件触发格(当前图 `entities` 能认出的事件 / 隐藏道具，认法复用任务 83、99 已有的);
   - 目标正好是计划路线里的一个路标;
   - 倒计时期间不放松也不加严，照本条规则;
   - `go` 的目标是地图号 / 地图名(去别的图)不在本条范围。
3. **拦的时候**:不执行，回一段话：这一段有计划(目的地、还剩哪些路标、下一个是什么),请用 `route()`(不带参数)接着走，或者用 `route` 改路标，或者 `plan_stage(replan: true)` 重做计划;确实要走坐标就带 `leave_incomplete`(复用现有参数)写具体理由，放行并记一条(不算欠账，写进活动日志，方便统计)。
4. **衡量**:`metrics`(任务 64)的工具表里分开统计 `go`(坐标)、`go`(地图)、`route`,并统计“被计划拦下的 go”和“带理由放行的 go”次数，方便以后比。
5. **提示词**:在说移动的地方加一句：有阶段计划时，这一段里不要用 `go` 走坐标，用 `route` 接着走;隐藏道具格、触发格这类没有名字的格子除外。只加，不改原有段落意思，不写具体关卡的攻略。
6. 开关进 `Config`(默认开)。

## 测试

- 有进行中的计划、人在这一段里、`go` 坐标 → 拒绝，文字里有下一个路标和 `route()` 的用法;
- 目标是事件格 / 隐藏道具格 / 计划路标 → 放行;
- 带 `leave_incomplete` → 放行并记一条;
- 没有计划、或人不在这一段里 → 照旧;
- `go` 地图名 → 照旧;
- `metrics` 分开统计;
- `npm run check` 全过。
