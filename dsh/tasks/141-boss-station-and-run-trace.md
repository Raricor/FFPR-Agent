## 起因(11-11 11:57 真机，`scripts/run-plan.mts` 第二次单独执行风之神殿计划)

任务 140 修好后，执行器自己走对了路(202 → 203 → 204 → 203 → 西楼梯 (9,15) → 205),途中 3 场普通战斗按计划规则表打完、全员满血，用时 1.4 分钟，模型调用 0 次。停在 205 (14,12),报例外 `stuck`:「第 1 站「205:14,11」没做成：「第 1 站 首领」连续失败 2 次：走了 3 跳:…」(说明被截断了)。
首领巨翼猛禽站在楼梯口 (14,10)/(14,11) 一带;游戏文件 `maps/205.json` 的事件里有 `sc_e_0016:コリジョンA` (13,11)、`コリジョンB` (15,11)(首领两侧的碰撞物件)。首领格本身走不上去，要站在旁边面朝它按确认才开战(攻略:“interact with the boss by the stairs leading up”)。

另外：命令行版执行器不写活动日志，失败原因又被截断，Claude 看不到每一站做了什么。

## 做法

1. **首领站**(`do: "boss"`):
   - 先按计划 `healFirst`/`saveFirst` 补满、存档(沿用 136 的规则);
   - 到达：目标格是首领本身(实体/事件/碰撞物件所在)时，走到它旁边能站的格(优先目标格的正下/正对方向),面朝首领按确认;目标格是剧情触发格(`sc_e_`/`ev_e_` 触发区)时，走上去;
   - 开打后用计划里这个首领的规则表(装成首领表，战术官停着);
   - 打赢 → 记 `bossesWon`,翻完战后剧情继续下一站;打输 → `boss-lost`;
   - 开战前出现的对话照常翻页;没开战(按了确认没反应)换另一侧再试，都不行才例外，说明里写清试过哪些格和朝向。
2. **过程日志**:执行器每一步(出发准备、每站开始/到达/动作/结果、每场战斗开始/结束/用了哪张表、每次重排、每个例外)写一行到:
   - 命令行：`.deps/tmp/plans/run-<时间>.log`(路径由参数给，默认这个),终端也打一行摘要;
   - 插件里：活动日志(`kind: "plan"`),供网页侧栏和 Claude 的监控看;
   - 例外的 `detail` 不截断(太长时写进日志全文，报告里留前 500 字 + “完整见日志”)。
3. 测试：假桥插件——首领格被占，从下方调查开战、按首领表打、赢了继续;第一侧没反应换另一侧;剧情触发型首领走上去;过程日志行的格式;`npm run check` 全过。
