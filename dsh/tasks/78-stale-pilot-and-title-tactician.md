# 任务 78:试玩助手进程没了却干等;标题画面误叫战术官

工作目录 `dsh/`。只许改 `src/engine/`、`src/plugin/`、`test/`。不碰 `../bridge/`、`../deploy/`、`../agent/`,不碰 git,不连真的笔记本(测试用替身 `runPs`/假 ssh)。

## 起因(11-09 真机)

1. **试玩助手进程没了,命令却一直等到超时。**
   - 早上笔记本离家,一轮工具调用断在半路;晚上笔记本回来、游戏重开。笔记本上 `C:\ffpr\session\pilot\agent.json` 还是前一天的(里面的 pid 早已不存在)。
   - AI 调 `advance_story`,`sendSsh`(`src/engine/link-pilot.ts`)的脚本只检查 `agent.json` 在不在,在就放下 `*.cmd.json` 干等,`story` 等了 5 分钟,直到我手动删掉 `agent.json`、重启试玩助手才返回。
   - 现有的自动重启(`sendSshOrRestart` → `restartAgent`)只认“`agent.json` 不存在”这一种报错;能识别“文件在、进程没了”的 `agentProcess`/`ensureAgent` 只在每轮开头调用一次。一轮跑到一半笔记本重启过,就没人管了。
2. **标题画面叫了 3 次战术官。**
   - 游戏还停在标题画面(场景 `Title`,地图 0)时,AI 调 `look_around`,23:47 前后连开了 3 个“战术官 地图 0”子会话,战术官还认真写了“地图 0 没有记录,先去城镇补货”这类建议,AI 当真了。
   - `look_around` 的完成度一行还把地图 0 叫成“世界地图”。

## 做法

1. `sendSsh` 的 PowerShell 脚本里,`agent.json` 在的时候顺便读出 pid,用 `Get-Process -Id` 看进程在不在(同一次 SSH,不加来回;`agentProcess` 的注释写了 SSH 登录看得见桌面会话的进程)。进程不在就抛和“文件不存在”**同一句**报错,让 `sendSshOrRestart` 现有的重启、重发一次接住。读 pid 失败(文件坏了)也按不在处理。
2. 等结果的循环里,每隔约 5 秒再看一次这个 pid;进程中途没了,立刻抛一个**不同的**报错(中文,说明试玩助手进程退出、命令没有完成),**不自动重发**(命令可能执行了一半,重发会重复按键)。
3. 战术官:当前地图号为 0、为 null,或场景是标题画面(不在地图上)时,所有触发战术官的路径都不叫(新地图、新怪、首领准备、队伍变化等,先找全入口,在一处把关)。
4. 完成度那一行:地图 0 / 不在地图上时不要说“世界地图”,说“不在地图上(可能在标题画面或切图中)”之类,或者干脆不出这一行。
5. 数值(检查间隔)放进 `Config`,默认 5 秒。

## 测试

- `sendSsh`:替身 `runPs` 断言生成的脚本里有 pid 检查;模拟“agent.json 在、进程不在” → 自动重启一次并重发;模拟“等待中进程退出” → 报新错误、不重发。
- 战术官:地图 0 / 标题场景时 `look_around` 等工具不调 tactician(用计数替身);正常地图照旧调。
- `npm run check` 全部通过。
