## 起因(11-11 11:41 真机，第一次用 `scripts/run-plan.mts` 不经过模型执行段计划)

计划第 1 站 `{"to":"205:14,11","do":"boss"}`(风之神殿 3 楼楼梯口的巨翼猛禽),人在 202 (26,14)。执行器立刻报例外:「第 1 站「205:14,11」走不到：地图 205 里从落点 (19,20) 走不到 (14,11)(按碰撞缓存)」。
205 被墙分成东西两块：从 203 有两个楼梯上来——到 205 (19,21) 落在东块，到 205 (9,21) 落在西块;首领在西块(攻略：先走东楼梯拿皮帽、回来，再走西楼梯上去)。跨图规划只选了“去 205”,没看目标格 (14,11) 在 205 的哪一块，选了东楼梯。

## 做法

1. `mapPath`/`travelToMap` 以及路线执行器、段执行器规划“去某张图的某一格”时，终点是(地图, 目标格所在的块)——用任务 75 的 `RegionIndex`(有碰撞缓存或游戏文件碰撞的图);只选落点在同一块(或经图内单向边能到)的入口;都不行才报“走不到”,并在说明里写出“目标在 205 的西块，能进西块的入口是 203 →(9,21)”这类信息。
2. 没有碰撞的图照旧(整张图一个节点)。
3. 测试：小数据——一张图被墙分成两块、两个入口各落一块，目标在 B 块 → 选 B 块的入口;真实数据(文件不在就跳过)——从 202 (26,14) 规划去 205 (14,11) 选的是落在 (9,21) 的那个楼梯。`npm run check` 全过。
