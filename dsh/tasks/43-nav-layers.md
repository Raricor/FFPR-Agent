## 起因

- FF5 的火力船，两轮都卡在**地图 261**("门/通风口大厅"):
  - 10-27 那一轮的笔记写着：可到达的只有大厅和一圈走廊，“所有未去过的出口都在够不到的区域”;
  - 11-03 这一轮，AI 玩家说“层间地板机关一时没解开”，停了下来。
- 用户 11-03 定了：游戏怎么玩让 AI 自己想，出问题由 Claude 分析、改代码。Claude 在现场抓了数据，结论是**我们的寻路用错了层**，不是 AI 不会走。

## 现场数据(`test/fixtures/nav/map261-firepowered-ship.json`,11-03 在 261 号图的 (17,21) 抓的)

- `collision`:两层(`layers[0]`、`layers[1]`),每层 36 行，`searchLayer: 1`,`playerCell: [17, 21]`。
- `route`:对 8 个出口调用桥插件的 `route`,每个都返回
  - `"theirs": [17, 21, 1]`(游戏认为人在**第 1 层**);
  - `"ours": [17, 21, 0]`(我们以为在第 0 层);
  - `"tries": {"theirs": 0, "simple": …, "used": "simple"}`,也就是游戏自己的寻路一次也没成，用的是后备的简单走法。
- `entities`:47 个，其中 7 个出口(`GotoMap`):

  | 格子 | 去往 |
  | --- | --- |
  | (10,25) | 263 |
  | (13,7) | 264 |
  | (20,13) | 265 |
  | (6,18) | 265 |
  | (20,22) | 256 |
  | (16,25) | 268 |
  | (18,18) | 262 |

- 还有 `cells24`(玩家周围半径 24 的地形码)、`pos`。

## 现在的做法(`nav.ts`)

- 把一张图的所有碰撞层**合并成一张平面网格**再走(`nav.ts` 第 314 行附近的说明)。
- 两层叠在一起的图，一合并，上层的通路和下层的墙会混在一起;再加上起点的层是错的。

## 要做的

1. **先读懂数据，再写结论**:
   - 两层各自的码是什么意思(1、0、3、5……;以前修过楼梯的 3、5,见 `bridge/README.md` 的 `collision`);
   - 哪些格子是换层的楼梯或通道;
   - 从 (17,21) **第 1 层**出发，按层走、经楼梯换层，7 个出口各自能不能到、怎么到。
   - 写进回报。到不了的，说明卡在哪里，可能要开关或传送带。
2. **寻路按层走**：位置带上层号(起点的层取桥插件 `collision.searchLayer`,或 `route` 的 `theirs` 第三个数);只在楼梯 / 换层格切换层;不再把所有层合并成一张。
   - 单层的图，行为不能变(现有测试全过)。
3. `walk_to` / `go_to` 的结果和地形图(`terrain`)，要让模型看得出“这里有两层、现在在第几层、楼梯在哪”。地形图上用不同的字符标出楼梯，并在图例里写明。
4. 注释写清楚日期和起因(火力船 261,两轮都卡)。

## 测试
