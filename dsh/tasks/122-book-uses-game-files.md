# 任务 122:路线书用上游戏文件(剧情站坐标、存档/回复点)，执行器接上「回头学」段

工作目录 `dsh/`。可以改 `src/engine/stage/route-book.ts`、`route-book-render.ts`、`book-plan.ts`、`route-book-load.ts`、`src/engine/route/`(只为执行「回头学」段)、`scripts/routebook.mts`、`test/` 下相关测试。**不碰** `src/engine/regions.ts`、`src/engine/skills/`、`src/engine/nav.ts`、`src/engine/knowledge/`(任务 123 的后续同时在改世界地图连通;知识模块只调用它的导出)。不改 `guide-types.ts`、`book-progress-types.ts`。不碰 `../bridge/`、`../deploy/`、`../agent/`,不碰 git,**不连笔记本**,**不用 docker、不绕开沙箱**。游戏数据只在 `../.deps/`,测试数据自己编。

## 起因(11-11)

任务 121 让知识模块用上了游戏文件(宝箱按英文名对上，图尔村 11 个全对;遇敌按每张图的 `monster_set_id`;三语物品名;存档点 36、回复点 68)。路线书还有三处没用上:
1. 剧情/对话/机关站没有坐标，执行时只能交回模型(或碰运气“唯一没触发的剧情事件”)。游戏文件里每张图的剧情事件触发物件(`maps/<id>.json` 的 `events`:名字如 `sc_e_0021:ゾックの家…`、格子或矩形、脚本编号)、NPC(`npcs`)、存档点、回复点都有坐标。
2. 攻略说的回复点(洞窟的泉水、风之神殿 1 楼的壶)以前“没对上真实的点”,现在知识模块有 `restorePointsIn`。
3. 任务 119 加的「回头学青魔法」「回头补图鉴」段，执行器(任务 117)还不执行。

## 做法

1. **剧情站配坐标**:一节里没坐标的剧情/对话站，按顺序配这一节所在图里的剧情事件触发物件:同一张图里按事件编号先后(`sc_e_` 后的数字)、本档剧情旗标(能读就用，读不到就按顺序)配;对话站优先配 NPC(攻略原文里的人名/职务对上 NPC 的名字或三语名，对不上就不配)。配上的写「游戏文件：事件 sc_e_0021(ゾックの家…)」作依据;配不上照旧交回。执行器对配上的站：走到触发格(矩形取最近的可走格),触发后翻完剧情。
2. **存档点、回复点**:用知识模块的真实点(地图 + 格子)。攻略提到回复(“泉水”“壶”)的那一步，同一张图有回复点就配上;执行器在进首领前、HP/MP 低时优先用(沿用现有补血规则的接口)。
3. **执行「回头学」段**:执行器把「回头学青魔法」「回头补图鉴」段当成普通段执行(刷怪站 `until.blueMagic`/`until.bestiary`,只有本档确实没学/没登记、而且队里有青魔导士(青魔法)时才执行;否则跳过并在进度里写原因)。
4. 命令行脚本重跑，路线书里剧情站有坐标的比例写进总表(新列「剧情站有坐标」)。

## 测试

- 脚本在 `/tmp` 副本带真实 `.deps` 跑一次，把「洞窟 → 海盗船」「风之神殿」两段的站点表贴进回报;
