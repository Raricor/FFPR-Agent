# 任务 100:路线里加“刷怪”路标——阶段官能安排在哪个区域刷到什么为止，`route` 一口气执行

工作目录 `dsh/`。可以改 `src/engine/route/`、`src/engine/stage/`(`types.ts` 只能加可选字段或新的联合成员，不改已有字段)、`src/plugin/stage-officer.ts`、`src/engine/game.ts`(只为把 `route` 的 `grind` 路标接到现有 `grind`)、`src/engine/prompt.ts`(只改 `route` 工具说明)、`test/`。不碰 `../bridge/`、`../deploy/`、`../agent/`,不碰 git,**不连笔记本**,**不用 docker、不绕开沙箱**。

## 起因

用户 11-10:`go` 调得太多，希望一进入一段(比如进卡纳克城到打液态火焰)就把整段行动推演好——开宝箱、触发机关、存档，**以及要刷图鉴的话在什么区域范围内刷**——让移动变成连续的行为。用户也要求像图鉴一样规划青魔法(哪些怪会放、会不会错过、要不要在这里刷)。

现在 `route` 的路标只有走到、`open`、`save`、`talk`;刷怪要 AI 另外调 `grind`。`grind` 已有(任务 47、68):在当前地图 / 世界地图区域来回走、按规则表打、可以按图鉴登记停，任务 68 起按遇敌概率定预算(以后还会出现的刷到平均场数 3–15 场就放弃并记欠账;会错过的刷到 5 倍平均场数或 40 分钟)。知识模块(任务 93)能回答某区域会遇到哪些怪、`blueMagicSources` 能回答还没学的青魔法由哪些怪放。

## 做法

1. **路标新动作 `grind`**:`{to, do: "grind", until: {bestiary?: [怪名或图鉴号], blueMagic?: [青魔法名], battles?: number, minutes?: number}, optional?}`。
   - `to` 是刷怪的地点(地图 / 世界地图区域，写法同 `go`);
   - 执行：走到 `to` 后调用现有 `grind` 的实现(不复制逻辑),停止条件按 `until` 映射:图鉴登记、学会青魔法(读已学列表，读不到就只按场数)、场数、分钟;没写场数时用任务 68 的概率预算;
   - 结果一行：刷了几场、登记了谁、学到什么、为什么停;
   - 倒计时期间跳过所有 `grind` 路标(写一行原因)。
2. **路线分析器**:`grind` 路标的预计用时 = 预算场数 × 每场秒数(`Config`)+ 走过去的时间;排序时把它放在顺路的位置(和宝箱一样参与排序)。
3. **阶段官**:`StagePlan.route` 的路标可以带 `do: "grind"` 和 `until`(在 `types.ts` 加可选字段);提示词加一两句：事实单里本档图鉴缺的怪、还没学的青魔法，按“会不会错过”决定要不要安排刷，安排时写清地点和停止条件;`checkStagePlan` 检查 `grind` 路标：地点能解析、`until` 至少有一项、刷的怪按知识库确实在那个地点出现(查不到就作为问题报出)。
4. **`route` 工具说明**加 `grind` 的写法(一两句，不写具体关卡的攻略)。

## 测试

- `route` 带一个 `grind` 路标：走到、调 `grind`(替身)按 `until` 停、接着走下一个路标;
- 倒计时期间跳过 `grind`;
- 分析器把 `grind` 排在顺路位置，预计用时含场数;
- `checkStagePlan`:`grind` 地点不出这只怪 → 报问题;`until` 为空 → 报问题;
- `npm run check` 全过。
