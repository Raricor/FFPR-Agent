# 任务 131:路线书驱动——进入下一节就自动出计划并执行，AI 只处理交回站

## 起因(11-11 真机验收，用户定的方向)

“洞窟入口 → 法利斯入队”这段的官方阶段统计：工具 130 次(go 40、route 6),**按计划走了 0 站**,52 分钟;目标是模型思考 ≤ 5 次、go 0 次。原因:
1. 自动出计划只在 `stageBeforeTravel` 里、只认“从城镇/世界地图去另一个地区的副本”(`game.ts` 约 5047 行 `isOtherRegionDungeon`)。去城镇(图尔村)、出入世界地图都不按路线书来;每次进出世界地图还生成一份目标是“世界地图”的空计划(统计「Map_10010」:工具 2 次、走了 0 站)。
2. 计划是旧代码生成的(排了已做完的站、混进后期的怪),修好上线后模型不再信任它，6 次写 `leave_incomplete` 绕过，自己找剧情触发点(海盗船“转舵”找了 3 分钟，路线书里有这一格)。
3. 统计标签显示资源名(`Map_30021_3`)。

用户的方向(11-10/11-11):长时间规划，走路、开箱、战斗由代码一口气做;AI 介入要少;出发没备齐就硬拦。

## 做法

1. **按“节”驱动**:引擎跟踪“当前所在的路线书节”(由当前地图在路线书里属于哪一节决定;世界地图上取“下一节”)。以下时机检查一次:进入新地图后第一次调用移动类工具(`go`/`route`/走路类)前，以及 `route {}`。
   - 没有进行中的计划，或进行中的计划属于别的节、或是旧版本生成的 → 结算旧计划(写阶段统计),按路线书为当前节(从现在的进度开始，沿用任务 126 的起点规则)生成新计划;有阶段官就照旧让它补药品/职业/等级，路线一律用路线书的。
   - 不再生成目标是世界地图、没有站的空计划;路线书覆盖不到的地方(没对上的节)保持旧行为。
2. **计划版本**:计划记录带“路线书代码版本 + 路线书数据的摘要”(比如站点列表的哈希);加载时不一致就视为过期，按第 1 条重做。
3. **执行**:有进行中的路线书计划时:
   - `route {}` 照旧执行;
   - `go` 指向计划覆盖的图(坐标、地名、地图号都算)且不是计划里的站 → 直接按计划走(沿用任务 113 的 `stageGoFollowPlan`,把地名/地图号也纳入);指向计划外的图(比如城里的商店，不在计划里)→ 照旧走，不拦;
   - 首次为某一节生成计划时，工具结果开头写一句“已按路线书为「节名(中文地区)」生成计划，共 n 站(宝箱 x、剧情 y、交回 z),代码会按计划走;处理完交回站再 `route {}`”。
4. **统计标签**用中文地区名(路线书节名 + 中文地区),不用资源名。
5. **提示词**:只改 `route`/`plan_stage`/`go` 那几行，说明“进入新的一节代码会自动按路线书出计划;移动时代码按计划走;交回时只处理那一站”。不加打法建议。
6. Config:`routeBookAutoPlan`(默认开)。
