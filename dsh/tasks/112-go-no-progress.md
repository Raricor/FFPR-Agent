# 任务 112:`go` 不收敛就停下，并留下每次重新规划的轨迹

工作目录 `dsh/`。可以改 `src/engine/skills/move.ts`、新建 `src/engine/skills/move-trace.ts`(或类似名字)、`test/`。不碰 `src/plugin/config.ts`、`src/engine/game.ts`、`src/engine/stage/`、`src/engine/route/`、`src/engine/prompt.ts`(任务 113 同时在改),不碰 `../bridge/`、`../deploy/`、`../agent/`,不碰 git,**不连笔记本**,**不用 docker、不绕开沙箱**。

## 起因(11-10 真机，新游戏开场，世界地图，骑陆行鸟不遇敌)

- 模型调 `go {"to": [175, 140]}`(泰空陨石地附近),14:10:46 发出，到 14:19:5x 网页重启打断时**跑了 9 分钟还没回结果**。
- 我在外面每 2 秒查一次位置：(160,118) …… (175,143) 面朝下停了约 10 秒 → 2 秒后到了 (163,144),又往别处走;这期间桥插件 `cells` 查询每 0.3 秒一次，一直没停。
- 网页重启后模型在新的调用里发了**同一个** `go [175,140]`,25 秒就到了：(161,120) → (174,144) 往右 → 切图进地图 189。
- 所以同一个目标第一次怎么也到不了，第二次一下就到了。疑点：
  1. 一次 `navigate` 的上限只有 `MAX_WALK_TURNS = 200` 轮，没有总时长上限，也不看有没有在靠近目标;
  2. 任务 83 起，事件格的“走不过去”只对本次调用生效(`recordBlockedStep(..., !eventAhead)` 那两处)。如果第一次踩入口没切图，入口格或它旁边的格在本次调用里被剪掉，目标就从此到不了，只能一直重新规划。请对照代码确认或排除这个推测，回报里写结论。

## 做法

1. **不收敛就停**:一次 `go`(`navigate`)里，
   - 总时长超过上限(世界地图和其他地图可以分开，默认值你按现有每格耗时估一个合理的数，写清怎么估的)就停;
   - 连续 N 次重新规划(默认 6)后，离目标的最短距离(按当前已知地图的步数，算不出来就用曼哈顿距离)一直没有比之前最好的更近，也停;
   - 两个上限照现有 `carryRepeatLimit`/`carryTotalLimit` 的写法：导出默认常量，`MoveState` 上可以覆盖(接进插件 Config 是后面的小任务，本任务不碰 `config.ts`);
   - 停下时工具结果用中文写清：走了多久、离目标最近到过哪一格、最后几次放弃的原因、本次调用里剪掉了哪些格;建议“换一个相邻格作目标 / 用 look_around 看入口 / 原地再试一次(新的调用会清掉本次剪掉的格)”。不替模型选目标。
2. **轨迹**:每次 `navigate` 调用写一条紧凑记录到 `.deps/ds/move-trace-<game>.jsonl`(路径同样可以从 `MoveState` 覆盖，默认值在新模块里按 `DEPS` 和作品算;测试一律用临时目录):起点、目标、每次重新规划的 {时刻、所在格、计划长度、放弃原因、本次剪掉的格}、结束原因。只追加，写失败只告警不影响走路;单条记录过长时截断重新规划列表(保留头尾)。
3. 如果确认了疑点 2:修掉它，比如入口/目标格本身不在本次调用里剪掉，或者剪掉以后让“到达目标的相邻格并面向它按一下”算到达。按你查到的实际原因改，回报里写清。

## 测试

- 假桥插件：目标格是入口，第一次踩上去不切图 → 不会无限重新规划，在上限内停下，结果文字含“最近到过”“剪掉了”;
- 连续不靠近 N 次 → 停;一直在靠近 → 不因 N 停(只受总时长限制);
- 轨迹文件的格式和截断;写失败不影响走路;
- 原有的 `go`/`navigate` 测试照旧通过;
- `npm run check` 全过。
