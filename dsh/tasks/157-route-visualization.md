# 任务 157:章计划路线可视化——宝箱顺序、站与站之间的路线、地图上的路径

工作目录 `dsh/`。可以改 `src/plugin/chapter-panel.ts`(或新建 `src/plugin/route-view.ts` 由 panel.ts 注册)、`src/plugin/panel.ts`(只注册路由)、`src/client/index.ts`、`src/client/globals.d.ts`(只在要声明新用到的前端接口时)、`test/`。可以 import、**不改** `src/engine/`(路线计算用现有的:`plan/dry-run.ts`、`route/distance.ts`、`regions.ts` 的连通块和格子 BFS、`nav.ts`/`skills/travel.ts` 的 `mapPath`、知识库地图导出;缺接口在回报里提)。任务 156 同时在改 `chapter-execute.ts`。不碰 `../bridge/`、`../deploy/`、`../agent/`,不碰 git,**不连笔记本**,**不用 docker、不绕开沙箱**。测试数据自编。

## 起因(11-11 晚，用户)

“每个宝箱的地点顺序是怎么样的，路径是怎么样处理的，怎么进行体现，我在 DSH 没有看到，你给我认真做好这一点。”

现在侧栏章面板只有站点文字表;看不出宝箱按什么顺序拿、站与站之间走哪几张图、多远、地图上怎么走。

## 做法

1. **路线数据路由** `GET /api/ffpr/chapter/route?game=ff5`(只读，不调桥插件，用当前章计划 + 章进度 + 地图记录 + 碰撞缓存 + 知识库导出;实时位置用网页里已有的当前位置，没有就用进度里最后的位置):
   - 每段：站点按执行顺序编号(①②③…),每站：图号/中文图名、格子、动作、说明、宝箱/隐藏道具的物品名、状态(做完/正在做/待做/跳过/失败);
   - 相邻两站之间的**路段**:经过的地图序列(图名)、跳数、估算格数和用时、能不能走到(不能就写原因),和执行器用的是同一套估算;
   - 本段统计：宝箱/隐藏道具 X 个(计划里几个、已开几个、跳过几个)、总路程。
2. **地图路径数据** `GET /api/ffpr/chapter/route/map?game=ff5&map=<id>`(缺省为当前所在图):这张图的宽高、墙/可走(碰撞缓存，含隐藏通道)、本图上的站点(编号、格子、动作、状态)、本图上各路段的实际格子路径(同一个格子 BFS/连通块算出来的折线;跨图的路段只画本图这一截，标出从哪个出入口进出)、出口位置、队伍当前格。
3. **前端**:
   - 章面板里每段加“路线”折叠区：编号站点列表(宝箱用醒目的标记和物品名)+ 站间路段一行一条(“③→④:203→205,2 跳,38 格,约 25 秒”),走不到的标红;
   - “地图”视图：画网格(墙深色、可走浅色、隐藏通道另一种颜色),站点画编号圆点(宝箱/首领/剧情/回复不同形状或颜色，做完的变灰),路段画折线，队伍位置一个醒目标记;可以在本段经过的地图之间切换;定时刷新跟面板一致;
   - 文字都由服务端算好，前端只排版;用 React 和现有面板的写法，不加依赖;`localStorage` 读写包 try/catch。
4. 性能：一段几十站、几张图，路由 < 1 秒;结果按计划版本 + 进度更新时间缓存。

## 测试

服务端：自编小章计划 + 小地图：站点编号顺序、路段的图序列/格数、走不到的原因、地图路径格子正确(经过隐藏通道)、跨图路段只画本图一截;前端按现有面板测试的方式补渲染检查。`npm run check` 全过，`npm run build` 后 `lib/client.js` 正常。
