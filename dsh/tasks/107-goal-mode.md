# 任务 107:目标模式——AI 自己一直玩下去，不靠人发“继续”;连续几轮没进展就停

工作目录 `dsh/`。可以改 `src/plugin/`、`src/engine/prompt.ts`、`src/engine/game.ts`(只为 `done` 工具的回复和进展信号)、`test/`(含 `test/fixtures/prompt/`)。`cordis.patch.yml` 已由 Claude 改好(见下),不要再改。不碰 `../bridge/`、`../deploy/`、`../agent/`,不碰 git,**不连笔记本**,**不用 docker、不绕开沙箱**。

## 起因

用户 11-10:AI 要有自己持续玩下去的办法。现在每一轮在 AI 写完总结后就结束，要人发“继续”(11-09 一夜手动发了 21 次);提示词还让它“完成目标或做不到时调用 done”。

dsh 自带目标机制(读装好的 dsh 里这几个包的 `README.zh.md`,**只用有文档的接口**):
- `@deepseek-ai/dsh-goal`:每会话一个持久的长期目标，跨轮次、恢复、重启都在;phase:`active`/`paused`/`blocked`/`complete`;
- `@deepseek-ai/dsh-goal-round-driver`:智能体空闲且有 active、已启用续行的目标时，自动排入下一个 Goal Round;Round 上限(默认 256)用完以 `round-limit` 阻塞;**会话恢复 / 网页重启后目标会“停用续行”,要人说一句继续才重新启用**;
- `@deepseek-ai/dsh-tool-goal`:让模型读取、创建(只能根据人的直接请求)、完成、阻塞目标;自主阻塞要求同一个阻塞条件连续 `blockedAfterConsecutiveRounds`(默认 3)个 Round;它自己会注册一段系统提示词;
- `@deepseek-ai/dsh-command-goal`:`/goal` 命令。

Claude 已在 `dsh/cordis.patch.yml` 的六个玩家预设(FF5 和 FF1–4、FF6)里挂上 `command-goal`、`tool-goal`(照标准预设的写法);顶层的 `goal`、`goal-round-driver` 本来就开着。

## 做法

1. **提示词**(`prompt.ts`):
   - 删掉“完成目标或者确定做不到时调用 done”这类说法，改成目标模式的说明：这个会话有一个长期目标(人会让你创建，比如“通关 FF5”);每一轮推进一段(比如一个阶段:`plan_stage` → `route` → 首领),轮末用两三句写进展;**不要因为一段告一段落就把整个目标标成完成**,只有真正达成才标完成;阻塞的标准照 `tool-goal` 自己的提示(同一条件连续 3 轮)。
   - 只改这几句和必要的衔接，不改其他段落意思，不写具体关卡攻略。相应更新提示词测试和夹具。
2. **`done` 工具**:保留(兼容旧会话),回复改成“目标模式下不用 done:这一轮写进展即可，系统会自动开始下一轮;整个目标真的完成时用目标工具标完成”。
3. **“没进展”看门狗**(插件，`src/plugin/`):
   - 每个 Goal Round(或每轮)结束时，看这一轮有没有进展信号：首次到达的新地图、开了宝箱、剧情事件、首领打倒、升级、存档、图鉴新登记、学会青魔法、买了东西(这些都在活动日志 / 事件流里有);
   - 连续 N 轮(`Config`,默认 3)一个进展信号都没有 → 用目标服务的有文档的接口把目标**暂停**(不是完成，也不是阻塞),理由写“连续 N 轮没有进展(最后几轮做了什么的一句话)”,并写进活动日志(`kind` 用现有的，文字以「目标暂停」开头,Claude 的监控会抓);
   - 查不到目标服务(没有挂 `dsh-goal`)时什么也不做。
4. 数值进 `Config`。

## 测试

- 提示词：不再出现“调用 done”;有目标模式的说明;夹具同步;
- `done` 的新回复;
- 看门狗：替身目标服务 + 替身事件，连续 3 轮无进展 → 暂停并写日志;中间有一轮有进展 → 计数清零;没有目标服务 → 不动;
- `npm run check` 全过。
