# 任务 155:规则文件提交后 AI 退场，执行器接管整章，出事停下等修复，不再回 AI

工作目录 `dsh/`。可以改 `src/engine/game.ts`(章工具注册、后台执行)、`src/plugin/player.ts`、`src/plugin/config.ts`、`src/plugin/` 下目标模式/唤醒相关文件、`src/plugin/panel.ts`/`chapter-panel.ts`(显示状态)、`src/client/index.ts`(面板)、`src/engine/prompt.ts` 和对照文件、`scripts/`(新建续跑命令)、`test/`。不改 `src/engine/plan/chapter-execute.ts` 的执行逻辑(任务 156 在改)、`execute.ts`、`chapter-validate.ts`、`dry-run.ts`。不碰 `../bridge/`、`../deploy/`、`../agent/`,不碰 git,**不连笔记本**,**不用 docker、不绕开沙箱**。

## 起因(11-11 晚，用户强调)

用户:“你这根本和我想得不一样。还是 AI 在操作。我给你一定要强调。一旦规则完成之后，AI 就停止接入，完全交给执行器。”

现在：模型调 `execute_chapter`,执行器一出例外就返回给模型，模型改计划、再交、再执行——第 1 章两个多小时里模型交了几十份计划，看起来就是 AI 在一步步操作。

## 要的流程

1. **规划(模型)**:`chapter_facts` → `read_guide` → 分段起草 → `submit_chapter_plan`。提交通过 = 规则文件定稿。
2. **接管(代码)**:提交通过后，代码在后台启动整章执行(`executeChapterPlan`,沿用续跑);工具结果告诉模型『规则文件已定稿，执行器接管第 N 章，本轮结束;本章跑完会再叫你规划下一章』。模型这一轮结束。
3. **执行期间模型不接入**:
   - 玩家工具里去掉 `execute_chapter`(模型不能再触发执行);
   - 执行期间，目标模式/自动续轮不发起新的模型调用(查清目标模式在一轮结束后怎么自动接下一轮，执行期间要挡住;执行结束再放开);
   - 若执行期间仍有模型轮次被触发，`chapter_draft_*`/`submit_chapter_plan` 一律回『执行器正在跑第 N 章，现在不能改规则』,不改草稿和计划。
4. **执行器处理不了**(兜底都失败):整章状态记 `blocked`(进度文件、报告、活动日志、侧栏章面板都显示『等待修复：第 x 节第 y 站：原因』),**不调用模型**,执行停在那里(游戏场面先收拾稳定)。
5. **续跑(操作员)**:新命令 `node scripts/chapter-resume.mjs`(经网页的新路由，比如 `POST /api/ffpr/chapter/resume`,用和 ask.mjs 一样的鉴权方式)让执行器用同一份规则文件从进度接着跑。也给一个 `--abandon` 让操作员结束本章执行、把规划权交回模型(只在规则文件确实要改时用)。
6. **一章跑完**:状态 `done` → 代码发起一轮模型对话(固定提示『第 N 章已跑完，报告如下……请规划第 N+1 章』),回到第 1 步。
7. 提示词(整章模式那段)改写成上面的流程：规划一次、提交即交接、执行期间不会被叫、出问题由运维修复后续跑。

## 测试

替身执行器：提交通过后后台执行启动、模型工具里没有 `execute_chapter`;执行中 draft/submit 被拒;执行 blocked 时不发起模型轮次;续跑路由让执行从进度继续;`--abandon` 后模型可以重新提交;执行 done 后发起下一轮(断言提示文字)。`npm run check` 全过。
