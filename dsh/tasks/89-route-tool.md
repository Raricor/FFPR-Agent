# 任务 89:把路线执行器接成工具——一段路只问 AI 一次，之后全由代码执行

工作目录 `dsh/`。可以改 `src/engine/game.ts`、`src/engine/prompt.ts`、`src/engine/route/`(含任务 87 的 `execute.ts`、`state.ts`,需要时可改)、`src/engine/completion.ts`、`src/plugin/config.ts`、`src/plugin/player.ts` 和 `test/`。不碰 `../bridge/`、`../deploy/`、`../agent/`,不碰 git,**不连笔记本**(测试全用替身桥 / 替身 pilot)。

## 起因(用户 11-10 的方向和真机数据)

- 用户：AI 介入的地方要减少;JRPG 很多思考可以提前做好;像卡纳克城限时逃脱这一段，只要走路、开宝箱、打仗不插入任何思考，大概率能通过。
- 11-10 第三次逃脱(倒计时 490 秒):打仗 9 场共 376 秒，AI 思考 26 步共 96 秒(想的时候人站在地图上，倒计时照走),走路约 30 秒;到点时在 105 号图打宝箱守卫。只走出口、代码一口气执行，约 240 秒就够。
- 已有的零件:
  - 任务 79 路线分析器 `src/engine/route/analyze.ts`(`analyzeRoute`);
  - 任务 87 路线执行器 `src/engine/route/execute.ts`(`executeRoute` / `resumeRoute`,通过 `RoutePorts` 注入 `position`、`goTo`、`act`、`replan`,带进度文件、偏离重排、7 种停下原因);
  - 走路 `go` 的实现：`Game.toolGo` → `goCell`(同图坐标)/ `travel.travelToMap`(跨图),任务 84 已能处理被传送带/陷阱带走;
  - 路上的战斗由现有执行器按规则表打;任务 86 起路上叫战术官在后台，不挡路;
  - 桥插件 0.14.3(任务 88,已装):`pos.timer` / `sample.timer` = `{active, seconds, paused}`(限时倒计时);`sample.gameover` = `{open, prompt: "continue"|"to-title"|null, cursor}`(游戏结束弹窗)。旧桥插件没有这两个字段时当作不存在。

## 做法

1. **新工具 `route`**(在 `prompt.ts` 的工具表里注册，说明写成中文，和其他工具一个口气):
   - 参数 `stops`:一组路标，按 AI 想去的地方给，代码排顺序;每个路标 `{to, do?, optional?}`:
     - `to`:地图号 / 地图名 / 当前图坐标 `"x,y"` / `"地图号:x,y"`,解析规则复用 `go` 的;
     - `do`:`open`(开宝箱、拿隐藏道具)、`save`(到存档点存档，只存 20 号位，复用现有存档技能)、`talk`(调查 / 对话)、省略(只是走到);
     - `optional`:可选路标(比如宝箱),默认 `do: open` 的是可选、终点不可选。
   - 可选参数 `end`:终点(比如出口地图),也可以就是最后一个路标。
   - `flee`:路上的普通战斗先逃(复用 `go` 的 `flee`)。
2. **ports 的实现**(在 `game.ts` 里，复用现有函数，不复制逻辑):
   - `position`:读 `pos`;
   - `goTo`:同图走 `goCell`,跨图走 `travelToMap`;
   - `act`:`open` 用现有的开宝箱 / 调查流程;`save` 用存档技能;路标是首领、要剧情选择、没有采购单的商店时，返回 `decision`;
   - `replan`:用地图记录 + 碰撞缓存调 `analyzeRoute`;
   - 进度文件 `.deps/ds/route-<game>.json`(路径进 `Config`)。
3. **执行中不问 AI**:
   - 路上普通的剧情对话自动翻(复用 `advance_story` 的翻页逻辑),遇到选项就停下交回;
   - 路上的战斗照现有执行器打，不叫战术官写表(倒计时期间连后台也不叫);
   - 首领战开打前停下交回(首领表由现有 `boss-prep` 流程准备)。
4. **倒计时**(`timer.active` 为真时):
   - 每个路标前，比较剩余秒数和“走到这个可选路标 + 从它走到终点”的预计用时(路线分析器的分钟数 + 每场预计战斗时间，`Config`,默认 45 秒 × 预计遇敌次数;遇敌次数先按每 30 格 1 次估，写成常量，注释写明是估计);
   - 不够就跳过剩下的可选路标，直奔终点，结果里写一行「倒计时剩 X 秒，预计还要 Y 秒，跳过宝箱 …」;
   - 倒计时期间离开本图不过完成度检查(不要求 `leave_incomplete`),路线结束时把跳过的宝箱记成欠账。
5. **停下交回 AI 的情况**:到终点;要决定(首领、剧情选择、商店);剩下的都走不到;同一路标连续失败 2 次;**`gameover.open` 为真**(立刻停，不按任何键，照实说“游戏结束了，弹窗是 …”);被取消。
6. **结果文字**:每个路标一行(到了 / 开了什么 / 跳过 / 用时),最后一行写停下原因;倒计时激活时写剩余秒数。30 行以内。
7. **提示词**:在说移动的那段加两三句：一段路上要去的地方已经清楚时，用一次 `route` 把它们都交给代码，不要一格一格地 `go`;`go` 留给单个目的地。只加，不改原有段落的意思。

## 测试

用替身桥 / 替身 pilot:
- `route` 三个路标(两个宝箱 + 出口)按排好的顺序走完，宝箱都开了，中途不回到 AI;
- 路上一场普通战斗、一段普通对话：自动处理，接着走;遇到选项：停下交回;
- 倒计时剩得不够：跳过可选宝箱、直奔终点，结果里有跳过那一行，欠账记下;
- 倒计时期间离开没完成的图，不被完成度检查拦;
- `gameover.open` 变真：立刻停，不按键;
- 进度文件写盘;网页重启后 `route` 不带 `stops` 调用时从进度文件接着走(或者给一个 `resume: true`,二选一，写明);
- 旧桥插件没有 `timer`/`gameover` 字段：照常工作;
- `npm run check` 全部通过。
