# 任务 159:存档站要有存上的证据;存不了的地方提交时就挡下

工作目录 `dsh/`。可以改 `src/engine/plan/execute.ts`、`src/engine/plan/chapter-execute.ts`、`src/engine/plan/validate.ts`、`src/engine/plan/chapter-validate.ts`、`src/engine/plan/dry-run.ts`、`src/engine/game.ts`(只改存档相关的 `planSave`/`planUsePoint`/`planPointAt` 和新加的查询)、`test/`。不碰 `src/plugin/`、`src/client/`、`skills/`(要用 `skills/save.ts` 的结果就读它的返回值，不改它)、`regions.ts`。不碰 `../bridge/`、`../deploy/`、`../agent/`,不碰 git,**不连笔记本**,**不用 docker、不绕开沙箱**。测试数据自编。

## 起因(11-11 真机，第 1 章风之神殿)

执行日志(`activity-ff5.jsonl`)原文:

```
第 10/13 站 存档 204 开始:首领前存档 20 号位
第 10/13 站 动作:存档:这里不能存档(「保存」是灰的),要到世界地图或存档点
第 10/13 站 动作:存档:这里不能存档(「保存」是灰的),要到世界地图或存档点
第 10/13 站 到达 地图 204 (6,9)
第 10/13 站 完成:首领前存档 20 号位
```

存档两次都失败，这一站却记成“完成”。下一站打首领时“首领前存档”又失败，就在没存档的情况下开打;要是全灭，游戏只能读回很早的档。存档站 `to` 只写了图号 `204`(没写格子),而这张图不是世界地图，执行器只按“到了这张图”就算这站完成。

## 做法

1. **执行**:存档站只有拿到存上的证据才算完成。证据是 `planSave`/`planUsePoint` 返回成功，最好再加一条能读到的硬证据(例如存档菜单里 20 号位的时间/次数变了，桥插件能读到什么就用什么，读不到就在回报里说明)。
   - 存不了时：先在本图找已知的存档点(`planPointAt`、恢复/存档点记录、知识库导出)，走过去存;本图没有，就照“可选站”记 **skipped**,原因写原话(“这里不能存档…”)。不许记 done,也不许只凭“到达”算完成。
   - 结构化日志(`run-<game>.jsonl`,任务 158)里，这一站的 `station.end` 要写 `result: "skipped"` 和原因，再加一条 `warn`:“首领前没存上档”。
   - 首领站里的“首领前存档”失败时一样写 `warn`。是不是因此回头去存，照现有兜底规则，不新加策略。
2. **提交时检查**(`chapter-validate`/`validate`/`dry-run`):存档站所在的图不是世界地图，`to` 也没写到存档点的格子，并且知识库里这张图没有存档点时，报一个问题，让规划的 AI 改计划，例如:「第 N 段第 M 站：图 204 不是世界地图，也查不到存档点，这里存不了档;改到世界地图或存档点的格子」。知识库里存档点的数据不可靠的话，降成警告，并在回报里说明数据从哪来、可靠到什么程度。
3. 已经记成 done 的旧存档站不用回头修。
